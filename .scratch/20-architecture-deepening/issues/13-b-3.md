# B-3 — toEntryType + FileTypeChecker 在 fs_read.ts 与 fs_find.ts 逐字重复，symlink 优先级不变量分散

Status: ready-for-agent
强度：试探性
域：fs
工具：fs_list, fs_stat, fs_find
文件：src/tools/fs_read.ts, src/tools/fs_find.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent B）

## 问题

toEntryType 函数与 FileTypeChecker interface 在 fs_read.ts（33-48 行）和 fs_find.ts（41-57 行）逐字重复定义：interface FileTypeChecker { isSymbolicLink(); isDirectory(); isFile(); } 与 function toEntryType(stats): EntryType { if(symlink) return 'symlink'; if(dir) return 'dir'; return 'file'; }。symlink 优先级（symlink > dir > file）是关键不变量——调换优先级会把 symlink 误判为 dir（因为 symlink 的 isDirectory() 在 lstat 下返回 false，但 stat 跟随链接下返回 true，混用 lstat/stat 时优先级错位产生哑错误）。该不变量分散两处，改一处忘一处即引入静默类型误判。EntryType 类型也在两处独立定义。

## 方案

提取到共享模块（建议 src/utils/fs.ts 或 src/contract/entry.ts），导出 type EntryType、interface FileTypeChecker、function toEntryType。fs_read.ts 与 fs_find.ts 改为 import。fs_du.ts 未用 toEntryType（直接 Dirent.isDirectory/isFile），若未来需统一 symlink 判定也可复用。

## 收益

symlink 优先级不变量单一事实源；fs_read/fs_find/fs_stat 共用；未来 fs 域新工具（如 fs_chmod、fs_chown）复用。收益规模小（15 行函数），但不变量关键且重复明确。

## 前后

**之前（浅）：**
fs_read.ts 与 fs_find.ts 各自定义 interface FileTypeChecker + function toEntryType + type EntryType，逐字重复。

**之后（深）：**
src/utils/fs.ts 导出 EntryType/FileTypeChecker/toEntryType；fs_read.ts、fs_find.ts import 共享定义。
