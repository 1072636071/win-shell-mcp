# E-2 — TCP 探测机器在 net_tcp 与 ping 中重复，cleanup 与超时逻辑各一份

Status: ready-for-agent
强度：值得探索
域：net
工具：net_tcp, ping
文件：src/tools/net.ts, src/tools/net_ping.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent E）

## 问题

net_tcp handler（net.ts 590-631）与 ping 的 probeOnce（net_ping.ts 85-124）各实现一套 TCP 探测机器：createConnection({host,port}) + setTimeout 超时 + socket.removeAllListeners()+socket.destroy() cleanup + once("connect")/once("error") 处理，约 30 行 × 2。两者语义高度同构（单次 TCP 连接尝试 + 超时），仅返回值不同：net_tcp 返回 {reachable, duration}，probeOnce 返回 rtt|null。cleanup 逻辑（clearTimeout+removeAllListeners+destroy）逐行重复。net_tcp 同步抛错→EINVAL fail，probeOnce 同步抛错→null，差异源于外层已做不同强度的参数校验。

## 方案

提取共享 tcpProbe(host, port, timeoutMs): Promise<{reachable: boolean, duration: number}>（duration 始终为尝试耗时，无论成败）到共享叶子（如 src/utils/tcp.ts 或 net.ts 导出）。net_tcp 直接用其 {reachable, duration} 构造输出；ping 用 reachable?duration:null 作为 rtt，外层汇总逻辑不变。同步抛错由 tcpProbe 统一返回 {reachable:false, duration:0}，net_tcp 外层已校验参数故不会走到该路径，ping 同理。

## 收益

消除约 25 行重复的 createConnection+cleanup 机器；cleanup 逻辑（socket.destroy+clearTimeout）单一事实源，避免一处改了另一处漏改（如未来需加 IPv6 优先或 keep-alive）；net_tcp 与 ping 的 TCP 探测语义由共享实现天然对齐。

## 前后

**之前（浅）：**
net.ts netTcpHandler: 内联 createConnection+setTimeout+cleanup(590-631)；net_ping.ts probeOnce: 内联 createConnection+setTimeout+cleanup(85-124)；两套 cleanup 逐行重复

**之后（深）：**
src/utils/tcp.ts: tcpProbe(host,port,timeoutMs)→{reachable,duration}（唯一 TCP 探测机器）；netTcpHandler 与 probeOnce 各自映射到 {reachable,duration} 与 rtt=null|duration
