# F-3 — 截断+标志模式跨 6+ 工具重复：truncated = raw.length > limit; text = truncate(raw, limit)

Status: ready-for-agent
强度：试探性
域：git
工具：git_diff, fs_read, text_diff, text_cat, shell_exec, pkg_run
文件：src/tools/git.ts, src/tools/fs_read.ts, src/tools/text.ts, src/tools/text_cat.ts, src/tools/shell_exec.ts, src/tools/pkg.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent F）

## 问题

const limit = getTruncateLimit(); const truncated = raw.length > limit; const text = truncate(raw, limit); 这一截断+标志两步模式在 git_diff、fs_read、text_diff、text_cat、shell_exec、pkg_run 等至少 6 处重复。truncate 已集中截断逻辑，但「截断后是否变了」的标志计算散落各处，且 text_diff 用了变体（const diff = truncate(rawDiff); const truncated = rawDiff.length > diff.length;）绕开 limit 变量，说明调用方对「截断判定」的理解已分叉。

## 方案

在 contract/output.ts 增加截断+标志一体辅助：export function truncateWithFlag(text: string, limit?: number): { text: string; truncated: boolean }。调用方解构 { text, truncated } = truncateWithFlag(raw) 即可，消除 limit 读取与标志计算的散落。

## 收益

消除 6+ 处重复与 text_diff 的变体分叉；截断判定单一事实源；新工具不再手写标志计算。代价：每处省 2 行，收益偏小，且 git_diff 的 withVerbose(verbose 时不截断) 语义仍需调用方处理。

## 前后

**之前（浅）：**
// git_diff
const limit = getTruncateLimit();
const truncated = rawDiff.length > limit;
const diff = truncate(rawDiff, limit);

// fs_read
const limit = ...getTruncateLimit();
const truncated = content.length > limit;
const truncatedContent = truncate(content, limit);

// text_diff（变体，已分叉）
const diff = truncate(rawDiff);
const truncated = rawDiff.length > diff.length;

**之后（深）：**
// contract/output.ts
export function truncateWithFlag(text: string, limit?: number) {
  const lim = limit ?? getTruncateLimit();
  return { text: truncate(text, lim), truncated: text.length > lim };
}

// 各调用方
const { text: diff, truncated } = truncateWithFlag(rawDiff);
