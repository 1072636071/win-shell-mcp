# C-3 — text_cat 与 readTextAutoDetect 的 stat+isDirectory+readFile 链路重复

Status: ready-for-agent
强度：试探性
域：text / search
工具：cat, text_grep, text_head, text_tail, text_wc, text_diff
文件：src/tools/text_cat.ts, src/utils/readText.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent C）

## 问题

text_cat.ts:86-93 内联 stat(path) → isDirectory 检查 → readFile(path)，与 readText.ts:23-29 的 readTextAutoDetect 前半段逐字重复。text_cat 未复用 readTextAutoDetect 的原因是需要在 buffer 阶段做字节范围切片（startByte/endByte）再解码，而 readTextAutoDetect 直接解码整个 buffer 丢弃了 buffer 句柄。结果是「stat + 目录拒绝 + readFile」这一稳定链路在两处各写一份，错误措辞还略有差异（text_cat「是目录」vs readTextAutoDetect「是目录而非文件」）。

## 方案

在 readText.ts 导出 readFileBuffer(path): Promise<Buffer>（stat + 非 directory 校验 + readFile，错误抛 EISDIR/ENOENT 供 failFromError 转）。readTextAutoDetect 改为 readFileBuffer 后 decodeBuffer；text_cat 改为 readFileBuffer 后自行做字节切片 + decodeBuffer + 行切片。统一错误措辞。

## 收益

消除 stat+isDirectory+readFile 链路重复与错误措辞分歧；text_cat 与 text 域其他工具共享同一文件读取接缝。删除该抽象会迫使两处复制目录校验逻辑 → 深化信号成立，但收益规模较小（约 4 行/处）。

## 前后

**之前（浅）：**
text_cat 内联 stat+isDirectory+readFile，readTextAutoDetect 内联同一链路，措辞略异

**之后（深）：**
共享 readFileBuffer(path) 返回 Buffer，readTextAutoDetect 与 text_cat 各自在 buffer 上做后续加工
