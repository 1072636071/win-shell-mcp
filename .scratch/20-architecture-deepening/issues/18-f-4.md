# F-4 — porcelain 解析纯函数（parseBranchLine/parseStatusLine/parseDiffFiles）未导出，测试仅经 handler 间接覆盖

Status: ready-for-agent
强度：试探性
域：git
工具：git_status, git_branch, git_diff
文件：src/tools/git.ts, tests/tools/git.test.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent F）

## 问题

parseBranchLine、parseStatusLine、parseDiffFiles 三个纯函数已从 handler 提取（局部性好），但未 export，测试只能通过构造完整 git 仓库 + 触发对应 git 输出间接覆盖。若解析逻辑有边界 bug（如 detached HEAD 的 ## HEAD (no branch)、porcelain v1 含空格路径的引号处理、rename 的 R 状态双路径行），需构造特定仓库状态才能触发，测试成本高、边界覆盖不全。

## 方案

导出三个解析函数，在 git.test.ts 增加纯函数单测：直接传入格式化字符串断言解析结果，覆盖 detached HEAD、引号路径、空行、短行等边界。

## 收益

解析逻辑可低成本低测边界；bug 不再需要构造完整仓库触发；测试与 git 版本/平台解耦。代价：导出内部函数略增公共面，但它们本就是稳定的 porcelain v1 解析。
