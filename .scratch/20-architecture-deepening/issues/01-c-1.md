# C-1 — text_grep 与 search_content 的逐行匹配谓词逐字重复，应提取共享 matcher

Status: ready-for-agent
强度：强烈
域：text / search
工具：text_grep, search_content
文件：src/tools/text.ts, src/tools/search.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent C）

## 问题

needle 准备（ignoreCase ? parsed.value.toLowerCase() : parsed.value）与逐行匹配三元（regex ? regex.test(line) : ignoreCase ? line.toLowerCase().includes(needle) : line.includes(needle)）在 text.ts:106-125 与 search.ts:262-301 逐字重复。两处注释互相指认（text.ts:106 写「与 search_content 一致」、search.ts:264 写「与 text_grep 一致」），作者已意识到重复但未提取。pattern 双模解析器（pattern.ts）与 hint 引擎（hints.ts）已共享，唯独最内层匹配谓词散落两处。若未来调整字面量匹配语义（如全字匹配、trim、忽略特定字符），需同步修改两处且 bug 隐藏在调用方式中——典型局部性违反。

## 方案

在 src/utils/pattern.ts 或新模块导出 prepareMatcher(parsed, ignoreCase): { test(line: string): boolean }，封装 needle/regex/ignoreCase 三者。text_grep 与 search_content 各自循环仅调 matcher.test(line)，收集策略（text_grep 收 ±context 行号、search_content 收 {file,line,text}）保持各自特化。不提取更大粒度（整个扫描循环），避免强行耦合两种 context 收集策略。

## 收益

消除约 12 行逐字重复；匹配语义变更收敛到单点；与已共享的 parsePattern/buildSearchHint 形成完整的 pattern 处理共享层，接缝一致。删除该抽象会迫使两处复制匹配复杂性 → 深化信号成立。

## 前后

**之前（浅）：**
text_grep 与 search_content 各自内联 needle 准备 + 匹配三元，注释互相指认但代码重复

**之后（深）：**
共享 prepareMatcher(parsed, ignoreCase) 返回 { test(line) }，两工具循环只调 matcher.test(line)
