# G-1 — archive.ts 内 createTar 与 createZip 的源枚举步骤逐行重复

Status: ready-for-agent
强度：试探性
域：archive / hash / json / meta
工具：archive_create, archive_extract
文件：src/tools/archive.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent G）

## 问题

createTar（L133-162）与 createZip（L212-263）各自维护一份「源枚举」逻辑：stat(src) → 判断是否目录 → 目录走 collectFiles / 单文件构造 {rel,abs,isDir,size,mode,mtime} → 遍历 files。这段前 7 行逐字节相同（含 root 计算与单文件 fallback 形态），仅内层对目录条目处理不同（tar 写目录头、zip 跳过目录由文件路径隐含创建）。当前 archive.test.ts 只做 round-trip 与格式推断，未覆盖 symlink/空目录/多源混合等边界，枚举逻辑若要改（如支持 symlink、过滤隐藏文件）需同步改两处，局部性摩擦真实存在。

## 方案

提取 enumerateSources(sources: string[]): Promise<FileInfo[]> 共享枚举器（stat + collectFiles/单文件 fallback），返回含目录条目的完整 FileInfo[]，由 createTar/createZip 各自决定如何消费（tar 写目录头、zip 跳过目录）。两函数的 for-of 体内层保留格式特定逻辑，外层枚举统一。

## 收益

消除 ~7 行逐字节重复；枚举逻辑改动（symlink 处理、过滤规则）收敛到单点；archive.test.ts 可对 enumerateSources 直接单测边界 case（混合源、单文件、深层目录），不必经 round-trip 间接覆盖。

## 前后

**之前（浅）：**
createTar 与 createZip 各写一份：stat → isDirectory? → collectFiles/单文件 → for-of。7 行重复，枚举逻辑分散两处。

**之后（深）：**
enumerateSources(sources) 统一枚举，返回 FileInfo[]；createTar/createZip 各自 for-of 消费，目录条目处理保留格式特定差异。
