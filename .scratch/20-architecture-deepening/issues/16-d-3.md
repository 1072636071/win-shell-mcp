# D-3 — process_kill Windows taskkill 与 run.ts killProcessTree Windows 分支局部重复

Status: ready-for-agent
强度：试探性
域：process / shell_exec / run_command / pkg
工具：process_kill
文件：src/tools/process.ts, src/exec/run.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent D）

## 问题

process.ts 的 killWindowsProcess（400-414 行）在 tree=true 时执行 taskkill /PID <pid> [/F] /T，run.ts 的 killProcessTree（75-92 行）Windows 分支执行 taskkill /PID <pid> /T /F（总是 /F）。两者都是 Windows taskkill /T /F 调用，存在局部代码重复。但语义有正当差异：process_kill 的 force 可选（用户可能想温和终止），run.ts 超时总是强制（超时即杀）。unix 分支则完全不同——run.ts 只 child.kill('SIGKILL') 杀直接子进程（超时场景，子进程是 spawn 出的 shell，杀 shell 够），process.ts 的 killPid tree=true 用 collectUnixDescendants + 逐个 process.kill 真正杀整棵后代树（用户显式要求杀树）。unix 分叉是语义正当的，Windows 分支是局部重复。

## 方案

提取共享辅助函数 taskkillTree(pid, force: boolean) 到 run.ts 或新文件 src/exec/kill.ts，process.ts 与 run.ts 共用。taskkillTree 封装 taskkill /PID <pid> /T [/F] 的平台分支与错误忽略。run.ts 的 killProcessTree 调用 taskkillTree(pid, true)，process.ts 的 killWindowsProcess 改为调用 taskkillTree(pid, force)。

## 收益

① 消除 Windows taskkill 调用的局部重复；② 统一 taskkill 错误处理（两者都忽略 taskkill 错误，但实现各自写了一份 .on('error', () => {}) 或 try/catch）；③ 收益较小，主要是局部性改善，让 Windows 进程树终止的唯一实现归 run.ts 模块。

## 前后

**之前（浅）：**
process.ts killWindowsProcess:
  const args = ['/PID', String(pid)];
  if (force) args.unshift('/F');
  if (tree) args.unshift('/T');
  await execFileAsync('taskkill', args, {...});

run.ts killProcessTree (Windows):
  spawn('taskkill', ['/PID', String(child.pid), '/T', '/F'], { stdio: 'ignore', shell: true, windowsHide: true }).on('error', () => {});

**之后（深）：**
src/exec/kill.ts:
  export function taskkillTree(pid: number, force: boolean): void {
    const args = ['/PID', String(pid), '/T'];
    if (force) args.unshift('/F');
    spawn('taskkill', args, { stdio: 'ignore', shell: true, windowsHide: true }).on('error', () => {});
  }

process.ts: taskkillTree(pid, force)
run.ts: taskkillTree(child.pid, true)
