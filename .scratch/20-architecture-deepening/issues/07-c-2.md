# C-2 — text_diff 的 LCS DP 与 hunk 合并算法孤立于文件内私有函数，缺乏独立可测性

Status: ready-for-agent
强度：值得探索
域：text / search
工具：text_diff
文件：src/tools/text.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent C）

## 问题

lineDiff（LCS DP + Int32Array 回溯）、naiveLineDiff（超大输入回退）、formatUnifiedDiff（hunk 合并：start <= last.end + 1）均为 text.ts 内私有函数（text.ts:382-536），未导出。测试 text.test.ts:954 的 describe('text_diff') 仅通过 handler 端到端验证，LCS 算法不变量（如「插入一行仅产生 1 个 add 操作」「完全相同返回空串」「hunk 合并不重叠」）无独立单测。算法 bug 隐藏在 DP 回溯边界与 Int32Array 索引中，端到端用例难以精确覆盖这些边界。

## 方案

将 lineDiff / naiveLineDiff / formatUnifiedDiff 提取到 src/utils/diff.ts 并导出，配独立单测 tests/utils/diff.test.ts：LCS 不变量（单行插入=1 add、对称性、空串边界）、hunk 合并边界（相邻、重叠、context=0）、LCS_MAX_CELLS 回退触发。text_diff handler 仅做读文件 + 调 formatUnifiedDiff + truncate。

## 收益

算法纯函数可独立单测，覆盖 DP 回溯与 hunk 合并边界；handler 变薄为读文件+格式化+截断的编排；与 readTextAutoDetect/splitLines/parsePattern 的提取风格一致。删除该抽象会迫使 handler 内联约 150 行算法且只能端到端测试 → 深化信号成立。
