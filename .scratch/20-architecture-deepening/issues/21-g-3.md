# G-3 — json.ts 的 getByPath 路径解析状态机 module-private，边界 case 难测且超界索引哑错误

Status: ready-for-agent
强度：试探性
域：archive / hash / json / meta
工具：json_get
文件：src/tools/json.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent G）

## 问题

getByPath（L35-78）是 44 行手写状态机，支持 .key / [n] / . 三种语法，module-private。测试只能经 jsonGetHandler 端到端构造（new_commands.test.ts 覆盖 .foo.bar / [1] / .a.b / . / .a[0] 失败），但未覆盖：嵌套数组 [[1,2],[3,4]] 的 [0][1]、超界索引 [100]（current[100] 返回 undefined 不抛——哑错误，调用方拿到 {value: undefined} 无法区分合法 undefined 与超界）、负索引 [-1]、连续点 ..（空 key）、不闭合 [ （L64 i++ 越界）、key 含数字 .a.1。handler 的 try-catch 把 getByPath 的 throw 转成 EINVAL，要测这些边界需构造完整 JSON 数据 + expr 且部分 case（如超界返回 undefined）不抛异常无法经 handler 失败路径覆盖。删除检验：删除 getByPath 抽象，handler 内联 44 行状态机，复杂性集中到 handler——是深化信号。

## 方案

提取为 src/utils/jsonPath.ts 导出 getByPath(data, expr): { value, exists }（改返回 exists 标志，与 batch.ts 的 getPath 形态对齐，超界索引返回 exists:false 而非哑错误 undefined）。json.ts handler 调用 getByPath 并按 exists 决定成功返回 {value} 或 fail(EINVAL, '路径不存在')。

## 收益

getByPath 边界 case（嵌套数组、超界索引、负索引、连续点、不闭合、key 含数字）可独立单测；超界索引从哑错误（返回 undefined）变响错误（exists:false → handler 报 EINVAL），符合 ADR-0013 向字面量收敛/响错误优先的可观测层原则；返回 {value, exists} 形态与 batch.ts 的 getPath 一致，未来若 batch 步骤引用需支持 [n] 数组索引可复用同一叶子。

## 前后

**之前（浅）：**
getByPath module-private 44 行，返回 unknown 或 throw；超界索引 current[100] 返回 undefined（哑错误）；边界 case 只能经 handler 端到端测且部分不抛异常无法覆盖失败路径。

**之后（深）：**
src/utils/jsonPath.ts 导出 getByPath 返回 {value, exists}；超界索引 exists:false → handler 报 EINVAL（响错误）；边界 case 独立单测；形态与 batch.ts getPath 对齐。
