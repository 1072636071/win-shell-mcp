# E-1 — HTTP 请求机器散落在 net.ts 与 net_download.ts，错误码与 URL 验证分叉

Status: ready-for-agent
强度：强烈
域：net
工具：net_get, net_post, net_download
文件：src/tools/net.ts, src/tools/net_download.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent E）

## 问题

net.ts 已为 net_get/net_post 抽出共享 HTTP 请求机器：fetchWithTimeout（AbortController+setTimeout+超时→NET_TIMEOUT/连接失败→NET_FAIL）、isAbortError、validateUrl（new URL+INVALID_URL）、mergeHeaders、headersToObject、buildHttpResult。但 net_download.ts 未复用，自己内联一套等价机器：AbortController+setTimeout（84-88 行）、fetch（91-94）、controller.signal.aborted 判断（127-132）。三处分叉：(1) 超时错误码——net_download 用 EXEC_TIMEOUT，net_get/net_post 用 NET_TIMEOUT；(2) HTTP 非 2xx 错误码——net_download 用 EXEC_FAIL，net_get/net_post 把非 2xx 当正常响应返回 status（语义不同，但 net_download 的 EXEC_FAIL 与 NET_FAIL 语义不一致）；(3) URL 验证——net_download 用 z.string().url()+EINVAL，net_get/net_post 用 validateUrl+INVALID_URL。同样是网络请求，AI 无法仅凭错误码一致识别「网络超时」「URL 非法」类别，违背输出优先级链第 1 项（一轮内完成决策）。

## 方案

把 net.ts 的 fetchWithTimeout 与 validateUrl 提取到共享叶子模块（如 src/utils/http.ts，零业务依赖），net_get/net_post/net_download 共用。net_download 改为：validateUrl 校验→fetchWithTimeout 发起→流式写入。错误码统一为 NET_TIMEOUT（超时）/NET_FAIL（连接失败与 HTTP 非 2xx）/INVALID_URL（URL 非法）。删除 net_download 内联的 AbortController+setTimeout 与 z.string().url()。注意：net_download 的流式写入（getReader+createWriteStream）与 net_get/net_post 的 text()+truncate 语义不同，这部分不共享，仅共享请求发起+超时+URL 校验机器。

## 收益

消除约 20 行重复的 abort/超时机器；错误码单一事实源（NET_TIMEOUT/NET_FAIL/INVALID_URL 全域一致），AI 可凭码统一识别网络类别并决定重试策略；URL 验证单一事实源。属接缝收敛：HTTP 请求机器从两处实现收敛到一处深模块。
