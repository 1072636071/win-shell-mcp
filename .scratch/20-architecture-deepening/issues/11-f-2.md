# F-2 — 11 个 git 工具中 5 个无测试覆盖（git_checkout/git_push/git_pull/git_clone/git_stash），含破坏性操作

Status: ready-for-agent
强度：值得探索
域：git
工具：git_checkout, git_push, git_pull, git_clone, git_stash
文件：src/tools/git.ts, tests/tools/git.test.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent F）

## 问题

tests/tools/git.test.ts（680 行）仅覆盖 git_status/git_log/git_branch/git_diff/git_add/git_commit 六个工具，git_checkout/git_push/git_pull/git_clone/git_stash 五个工具完全无测试（未 import、无 describe 块）。其中 git_push 的 --force 改写远程历史、git_checkout 的 paths 还原文件、git_stash 的 drop 丢弃 stash 均为破坏性操作，无测试意味着回归无护栏。覆盖率阈值要求 lines/functions/statements ≥85%、branches ≥84%，git.ts 1122 行的近一半 handler 未被测试触达，分支覆盖更难达标。

## 方案

为 5 个工具补测：git_checkout 覆盖切分支/建分支/还原文件/从源还原/互斥校验五条路径；git_push 覆盖默认 remote/指定 branch/force；git_pull 覆盖默认/指定；git_clone 覆盖 url+path；git_stash 覆盖 push/pop/list/drop 四 action。复用现有 initRepo/makeCommit 测试辅助。

## 收益

消除破坏性操作的回归盲区；分支覆盖向 84% 阈值靠拢；git_checkout 的多职责路径（F-1）被测试压力显性化，为拆分决策提供依据。
