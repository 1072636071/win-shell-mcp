# B-1 — fs 域四份递归目录遍历 → 统一目录树遍历深模块（walkTree + visitor）

Status: ready-for-agent
强度：值得探索
域：fs
工具：fs_list, fs_du, fs_find, fs_rm
文件：src/tools/fs_read.ts, src/tools/fs_du.ts, src/tools/fs_find.ts, src/tools/fs_write.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent B）

## 问题

fs 域存在四份独立的递归目录遍历实现，各自处理「递归控制 + 深度 + stat 策略 + symlink 策略 + 字段收集」，复杂性分散：(1) fs_read.ts 的 collectEntries（93-116 行）收集 FullEntry[]，recursive 开关，对每个条目 lstat 拿 type/size/mtimeMs；(2) fs_du.ts 的 computeDirSize（40-63 行）累计 {size,files,dirs}，总是递归，用 Dirent.isDirectory/isFile 判断，仅文件 stat 取 size；(3) fs_find.ts 的 walkFind（90-129 行）收集 FindEntry[]|string[]，maxDepth 限制，仅 verbose 时 lstat；(4) fs_write.ts 的 countEntries（202-212 行）递归计数，总是递归，用 Dirent。四份实现的 readdir+递归+相对路径计算+深度控制骨架重复，但 symlink 处理不一致（fs_list 当条目收集、fs_du 跳过、fs_find 当匹配、fs_rm 仅计数真实目录），无统一类型。真正的 bug 风险隐藏在调用方式：例如 fs_list 的 collectEntries 总是 lstat 每个条目（即使非 verbose + sort=name 时 Dirent 已够 type），大目录递归 lstat 性能损耗无法由调用方避免——局部性失败。

## 方案

抽 src/utils/walkTree.ts 深模块，接口形如 walkTree(root, visitor, options?: { maxDepth?, followSymlinks? })，其中 visitor: (dirent, fullPath, relPath, depth) => Promise<void>|void。walkTree 拥有 readdir({ withFileTypes: true }) + 递归 + maxDepth + relPath 计算 + symlink 目录不跟随（默认）的单一实现；调用方在 visitor 里按需 lstat、收集所需字段、应用过滤。各工具改写为：fs_list.collectEntries → walkTree + visitor 里 lstat 收集 FullEntry；fs_du.computeDirSize → walkTree + visitor 累计；fs_find.walkFind → walkTree + visitor 里 regex.test 收集；fs_rm.countEntries → walkTree + visitor 计数。symlink 策略由 Dirent 语义自然统一（isDirectory() 对 symlink 返回 false → 不跟入；visitor 内按需 lstat 判定 symlink 类型）。

## 收益

遍历骨架（readdir/递归/深度/relPath）单一事实源，新增遍历工具零重复；symlink 目录不跟随的不变量集中一处；maxDepth/recursive 语义统一（recursive = maxDepth: Infinity）；调用方只写 visitor（5-10 行）而非整个递归（10-20 行）；未来加并发遍历/取消信号/进度回调只改 walkTree 一处。删除检验：删除 walkTree 抽象，遍历复杂性分散回四处，每处虽简单但 symlink/深度不变量需各自守护——集中=深化信号。

## 前后

**之前（浅）：**
四处各自实现递归：collectEntries(lstat 全量)、computeDirSize(Dirent+条件stat)、walkFind(maxDepth+条件lstat)、countEntries(Dirent 计数)。readdir+递归+relPath 骨架重复四份，symlink 策略分散无统一类型。

**之后（深）：**
walkTree(root, visitor, { maxDepth }) 单一实现遍历骨架+深度+symlink 目录不跟随；fs_list/fs_du/fs_find/fs_rm 各自只写 visitor（按需 lstat、收集/累计/过滤/计数）。
