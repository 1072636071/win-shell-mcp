# A-1 — unix 系统信息解析逻辑与平台 I/O 耦合，无法在 Windows CI 测试（局部性摩擦）

Status: ready-for-agent
强度：值得探索
域：system / core / env
工具：system_disk, system_memory
文件：src/tools/system.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent A）

## 问题

system_disk 的 enumerateUnixDisks 与 system_memory 的 readSwapInfo 各把「解析 /proc/mounts、/proc/meminfo 的纯逻辑」与「readFile + statfs 的平台 I/O」耦合同一函数体内，且整体被 /* c8 ignore start */ 包围。项目定位是跨平台命令抽象层（CONTEXT.md：抹平 Win/Linux/macOS 差异），但 CI 仅 Windows，unix 解析路径完全无测试覆盖。纯逻辑已具函数形态但未导出，bug 隐藏在平台分发的调用方式中——这正是局部性摩擦的定义：纯函数仅为可测试性提取，但真正 bug 隐藏在调用方式（平台分发 + c8 ignore）中，无局部性。若 /proc/mounts 格式变化（如挂载点含空格、新伪文件系统类型），代码会静默坏掉而 CI 不报。

## 方案

把两处解析逻辑提取为独立导出的纯函数：parseProcMounts(content: string) → { mountPoint, fstype }[]（含 20 个伪文件系统 skip 过滤、逐行 split、字段提取）与 parseMemInfoSwap(content: string) → { swapTotal?, swapFree? }（含正则解析、SwapTotal/SwapFree 提取、kB→字节转换）。enumerateUnixDisks 与 readSwapInfo 退化为薄壳：只负责 readFile + 调用纯函数 + statfs。纯函数可在 Windows CI 上用样例 /proc/mounts、/proc/meminfo 字符串直接测试，无需 unix 环境。

## 收益

局部性：解析逻辑与平台 I/O 分离，bug 可在任一平台 CI 独立发现（删 c8 ignore 后纯函数路径可测）。杠杆：一处解析纯函数喂给平台薄壳，未来加 macOS 解析（如 vm_stat）复用同一接缝。测试覆盖：unix 路径从 0% 提升到纯逻辑 100%（I/O 薄壳仍 c8 ignore）。深化检验通过——删除该抽象会把解析逻辑散回平台函数，集中复杂性（每处都要重写 skip 列表与解析），确认是深化而非移动。

## 前后

**之前（浅）：**
enumerateUnixDisks / readSwapInfo 是浅模块：接口（返回磁盘条目/swap 信息）≈ 实现（读文件 + 解析 + statfs），解析逻辑与 I/O 耦合，整体 c8 ignore 不可测

**之后（深）：**
parseProcMounts / parseMemInfoSwap 是深模块：接口简单（字符串进、结构化数据出），实现含 skip 列表与解析规则；enumerateUnixDisks / readSwapInfo 退化为 I/O 薄壳，纯函数可独立测试
