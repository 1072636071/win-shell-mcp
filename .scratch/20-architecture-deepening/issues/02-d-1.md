# D-1 — run_command 绕过命令执行深模块自建 spawn 机器，行为已分叉

Status: ready-for-agent
强度：强烈
域：process / shell_exec / run_command / pkg
工具：run_command
文件：src/tools/run_command.ts, src/exec/run.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent D）

## 问题

ADR-0003 明确规定「命令执行机器集中在 src/exec/run.ts（深模块，接口只有 runCommand）」，CONTEXT.md 术语表亦声明「shell_exec、pkg_run、git 均调用它」。但 run_command.ts 在 28-129 行自建了一套完整的 spawn 机器 spawnCommand：自己 spawn、自己收集 stdout/stderr、自己 setTimeout 超时、自己 decodeBuffer 解码，完全绕过 run.ts。更严重的是行为已经分叉：(1) 超时时 run_command.ts 只 proc.kill('SIGKILL') 杀直接子进程，run.ts 用 killProcessTree（Windows taskkill /T /F 杀整棵树）；(2) run_command.ts 抛异常（throw spawnError、throw EXEC_TIMEOUT），run.ts 从不抛异常、返回结构化 RunOutcome；(3) run_command.ts 超时后仍 await close 事件，run.ts 超时立即 settle（避免 Windows 子进程持有 pipe 导致 close 永不触发的挂起）。这正是 run.ts 顶部注释所描述的「此前 shell_exec 与 pkg_run 各有一份且已分叉——pkg 超时杀进程树，shell_exec 只杀 shell，导致 Windows 上兜底执行超时后子进程仍在运行」反模式的重现。测试 tests/tools/run_command.test.ts 第 52-60 行只验证「超时返回 EXEC_TIMEOUT」，未验证「超时后子进程是否真的被清理」，bug 被测试盲区掩盖。

## 方案

删除 run_command.ts 的 spawnCommand 函数，handler 改用 run.ts 的 runCommand。run.ts 的 RunOutcome 已携带 spawnError/timedOut/exitCode/stdout/stderr/pid/duration，handler 直接映射到输出契约即可。需 run.ts 扩展 RunOptions 增加 maxOutputBytes 字段（run_command 的字节预算截断是 run.ts 唯一缺失的能力），或由 handler 在拿到完整 stdout/stderr 后做字符级截断（对齐 shell_exec 的 truncate 语义，顺带消除 D-2 的截断不对称）。signal 字段可由 outcome.exitCode===-1 && timedOut 推导，或 run.ts 扩展返回 signal。

## 收益

① 消除约 100 行重复 spawn 机器代码；② 统一进程树终止语义，修复 Windows 超时后子进程残留的潜在 bug；③ 统一「深模块从不抛异常」契约，handler 不再需要 try/catch + failFromError 的异常路径；④ 统一超时立即 settle，消除 Windows close 挂起风险；⑤ 测试可复用 run.ts 的进程树终止覆盖，不再需要 run_command.test.ts 单独验证清理。

## 前后

**之前（浅）：**
run_command.ts 自建 spawnCommand：spawn + 自收集 stdout/stderr + setTimeout + proc.kill('SIGKILL')（不杀进程树）+ await close（超时可能挂起）+ throw 异常。handler try/catch + failFromError。

async function spawnCommand(opts) {
  const proc = spawn(command, args, {...});
  // 自己的 stdout/stderr 收集 + maxOutputBytes 截断
  const timeout = setTimeout(() => {
    timedOut = true;
    proc.kill('SIGKILL');  // 只杀直接子进程
  }, timeoutMs);
  const exitCode = await new Promise(resolve => proc.on('close', resolve));  // 超时可能挂起
  if (spawnError) throw spawnError;
  if (timedOut) throw EXEC_TIMEOUT;
  return { stdout, stderr, exitCode, signal, truncated };
}

**之后（深）：**
run_command.ts 调用深模块：const outcome = await runCommand(command, args, { cwd, env, timeoutMs, encoding, stdin, maxOutputBytes }); 映射 RunOutcome 到输出契约。无 try/catch、无异常路径。

async function handler(raw) {
  const outcome = await runCommand(command, args, {
    cwd, env, timeoutMs, encoding, stdin,
    // maxOutputBytes 需 run.ts 扩展 RunOptions
  });
  if (outcome.spawnError) return fail(ErrorCode.EXEC_FAIL, outcome.spawnError.message);
  if (outcome.timedOut) return fail(ErrorCode.EXEC_TIMEOUT, `命令执行超时（${timeoutMs}ms）`);
  const stdout = truncate(outcome.stdout);
  const stderr = truncate(outcome.stderr);
  return ok({ stdout, stderr, exitCode: outcome.exitCode, signal: null, truncated: ... });
}
