# F-5 — git_log 空仓库检测依赖 stderr 英文字符串匹配，跨 git 版本/语言环境脆弱

Status: ready-for-agent
强度：试探性
域：git
工具：git_log
文件：src/tools/git.ts
来源：架构深化审查（jxx-improve-codebase-architecture，子 agent F）

## 问题

git_log 通过 stderr.toLowerCase().includes(does not have any commits | bad default revision head | unknown revision) 三选一判定空仓库。依赖 git 英文错误消息文本，若用户环境 LANG/LC_MESSAGES 非 C/POSIX（如德语/法语 git），stderr 文本变化则误判为 GIT_FAIL 而非空仓库。git 错误消息无稳定契约，跨版本亦可能改写。

## 方案

改用结构化预检：先 runGit([rev-parse, --verify, HEAD], cwd)，exitCode!==0 即空仓库，返回 { commits: [], count: 0 }；否则再执行 log。多一次子进程调用但判定不依赖 stderr 文本。或用 git log --exit-code 配合 exit code 128 判定（但仍需区分空仓库与其他错误）。

## 收益

空仓库判定不依赖 git 错误消息文本，跨语言/版本稳定。代价：多一次 git 子进程调用（约 10-30ms），仅空仓库路径触发；非空仓库无额外开销（log 成功直接返回）。

## 前后

**之前（浅）：**
const result = await runGit([log, ...], cwd);
if (result.exitCode !== 0) {
  const stderr = result.stderr.toLowerCase();
  if (
    stderr.includes(does not have any commits) ||
    stderr.includes(bad default revision head) ||
    stderr.includes(unknown revision)
  ) {
    return ok({ commits: [], count: 0 });  // 依赖英文 stderr 文本
  }
  return fail(ErrorCode.GIT_FAIL, gitError(result.stderr, log));
}

**之后（深）：**
// 结构化预检，不依赖 stderr 文本
const verify = await runGit([rev-parse, --verify, HEAD], cwd);
if (verify.exitCode !== 0) {
  return ok({ commits: [], count: 0 });  // 空仓库
}
const result = await runGit([log, ...], cwd);
if (result.exitCode !== 0) {
  return fail(ErrorCode.GIT_FAIL, gitError(result.stderr, log));
}
