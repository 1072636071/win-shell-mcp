# 预设目录 + 索引 + 首批 4 个预设文档

**Status:** ready-for-agent

**Blocked by:** 无——可立即开始（语法基线依赖 09 号工单已落地的默认极简输出形态，文档按该基线撰写即可，不阻塞落地）

**构建内容：** AI 需要编排多步 batch 时，可以在 `docs/batch-presets/` 下按场景查到现成模板：每个预设一个 markdown 文件，说明"什么时候该用 / 什么时候别用"，附一段可直接粘进 `batch_run` 的 `args` 的入参 JSON，再讲清楚每条断言与引用的编写理由，末尾标注适用版本与维护状态。入口是一个索引页，每预设一行（名称｜适用场景｜维护状态）。首批落地 4 个预设：读改写回、git 提交推送、批量文件采集、环境自检——覆盖真正高频的任务形态，AI 照抄即用，不必每次从零编排步骤数组与引用链。

**验收标准：**

- [ ] `docs/batch-presets/` 目录创建，内含索引文件 + 4 个预设文件（每个预设一个文件）
- [ ] 索引页每预设一行：名称｜适用场景｜维护状态，并提供指向各预设文件的链接
- [ ] 4 个预设齐全：
  - 读改写回：`cat` 读取 → `text_grep` 定位确认 → `text_replace` 替换（断言替换计数符合预期）→ 必要时复读校验
  - git 提交推送：`git_status`（断言变更集符合预期）→ `git_add` → `git_commit` → `git_push`，每步断言要点给出
  - 批量文件采集：`fs_list`（glob 过滤）→ 逐文件读取，演示整串单引用保类型的引用写法
  - 环境自检：`system_disk` + `env_get` + `system_info` 的组合快照，断言磁盘余量等阈值（`gt` 操作符示范）
- [ ] 每个预设文件结构统一：场景（何时用/何时不用）→ `batch_run` 入参 JSON（可直接粘进 `args`）→ 断言与引用的要点讲解（为什么这么断言）→ 适用版本与维护状态行
- [ ] 入参 JSON 一律以 09 号工单落地后的默认极简输出形态为基准，不默认带 `verbose`
- [ ] 断言操作符严格限 10 种枚举内（eq/neq/gt/gte/lt/lte/in/re/truthy/falsy），不出现枚举外的操作符
- [ ] 引用仅使用 `{{stepId.output.path}}` 形式；示例中步骤 `id` 全部显式命名（便于引用可读），不使用自动编号
- [ ] 语法基线核对清单逐项满足：断言操作符枚举、引用形式、步骤失败短路后果在"何时不用"中说明、步骤 id 显式命名
- [ ] 每个预设文件的维护状态行写明维护约定：`batch_run` 语法或相关工具输出变更的工单须同批检查本目录是否过时；过时预设改状态标注而非悄悄留存
- [ ] 语法事实与当前实现逐项一致（操作符数量、引用语法、默认输出形态），不出现"9 种操作符"式错误
