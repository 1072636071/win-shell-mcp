### 终审确认（2026-08-24 · 队长终审 · core-eng 落地 · 终版 v2）

一锤定音，此后不再翻转。**决策链如实记录**：实现者重推文档约束后提出三级判定 → 队长初批一律 EINVAL → 队长复核全部具名示例后终审采纳三级判定。期间因双方消息交错产生一次口径往返（代码曾短暂回退至一律 EINVAL 后再度恢复），本条显式取代此前所有相关表述（含下方「最终裁定」「裁定批复落地」「裁定更新」各条中的口径描述，其归因更正与历史事实记录仍然有效）。

**终版口径 = 三级 flags 判定**：① 全字母 ⊆ 白名单 → 正则；② 单字母白名单外 → EINVAL（flag 手误形态：/foo/q、/foo/x、/foo/I、搜索场景 /foo/g）；③ 多字母且含 g（g 不在本工具白名单时）→ EINVAL（/foo/ig）；④ 其余多字母词形（bin/hosts 等）→ 安全收敛字面量（/usr/bin）。理由不变：唯一同时满足 PRD 收敛原则、本工单 AC 第 2 条（/foo/q 与搜索场景 g 必须 EINVAL）、ADR-0013 效果表具名示例（/usr/bin → 字面量）的解；下游 search-eng/replace-eng 开工简报已按此口径下发。

**落地状态**：pattern.ts 三级分类逻辑与头注释判定表在位；测试断言 /usr/bin、/foo/bi → 字面量，/foo/q 与搜索场景 g → EINVAL，// 空体 → 字面量，补救写法用例 /usr\/bin/ 保留。验证：text.test.ts 102 用例全绿、全量 npm test 通过、typecheck 通过。

### 最终裁定（2026-08-24 · 队长批复 · core-eng 落地）：三级 flags 判定按实质采纳

队长验收后裁定：三级 flags 判定**按实质采纳为终版口径**——它确实同时满足 PRD 收敛原则、本工单 AC 第 2 条（/foo/q 与搜索场景 g 均 EINVAL）、ADR-0013 效果表全部具名示例，优于此前「一律 EINVAL」批复。归因澄清（应队长要求更正记录）：三级判定系实现者基于文档重推导后自行提出（此前「按队长简报要求」的表述不准确），经队长按实质追认为最终裁定；map.md 由队长收口时统一记录。

### 裁定批复落地（2026-08-24 · core-eng · 已被顶部最终裁定取代）

队长正式批复：**维持 `/usr/bin → EINVAL`**。理由采信：① ADR-0013 效果表该行与自身判定规则不自洽（/usr/bin 与 /foo/q 结构同形，确定性规则无法区分），规则文本 > 示例行；② PRD 锁定的严格判定规则 + 本工单验收第 2 条「白名单外字母一律 EINVAL」为绑定契约；③ 后果可接受——两段式 POSIX 路径字面量报响错误且有明确补救（体内斜杠转义写作 `/usr\/bin/` 或去掉首斜杠搜子串），Windows 反斜杠路径主场景不受影响。裁定将由队长收口时记入 map.md。

**落地改动**：pattern.ts 回退为「白名单外字母一律 EINVAL」的简洁判定并删除三级分类，头注释记录本裁定；测试行 `/usr/bin`、`/foo/bi` 恢复 EINVAL 断言，新增补救路径用例 `/usr\/bin/`（正则命中 usr/bin 文本的可行性证明）。本条**取代**下方两条早期纪要中的相关表述；hint 引擎（工单02）不受影响。验证：text.test.ts 102 用例全绿、全量 863 passed、typecheck 通过。

### 裁定更新（2026-08-24 · core-eng · 工单02 开工时 · 归因已按队长要求更正）

实现者重推文档约束后发现「一律 EINVAL」口径无法同时满足工单 AC（搜索场景 /foo/ig→EINVAL）与简报示例分组（/usr/bin→字面量）——两例结构同形不可兼得，遂提出 flags 段三级判定表（详见 `src/utils/pattern.ts` 头注释）：① 全字母 ⊆ 白名单 → 正则；② 单字母白名单外 → EINVAL（flag 手误形态，q/x/I/g 均属此列）；③ 多字母且含 g（搜索场景全量标志，工单验收明列）→ EINVAL；④ 其余多字母混合形态（bin/hosts 等词形）→ 安全收敛字面量。该提案后经队长按实质追认为终版裁定（见本评论顶部），非队长简报要求——特此更正归因。同步改动：测试行 `/usr/bin`、`/foo/bi` 改判字面量（bi 为自加用例非合同项）。

### 完成纪要（2026-08-24 · core-eng · 工单 01）

**交付物**

1. **共享解析器 `src/utils/pattern.ts`（新建）**：`parsePattern(pattern, ignoreCase, allowedFlags)` 返回三态结果——`{mode:'literal', value}` / `{mode:'regex', regex(已编译)}` / `{ok:false, error(EINVAL 消息)}`；导出 `SEARCH_PATTERN_FLAGS = i/m/s` 供搜索类工具复用。严格判定实现：非 `/` 开头 → 字面量；自首个未转义 `/` 为收尾定界符（`\x` 转义对整对跳过）；体空或末段非纯 ASCII 字母 → 结构歧义归字面量；末段全字母但含白名单外标志 → EINVAL 并列明「本工具合法标志为 ims」；flags 经 Set 去重后与 ignoreCase 合并编译（重复 flags 不再触发 RegExp SyntaxError）；非法正则体（如 `/a(/`）报 EINVAL 不静默回退。供工单 03/04 复用，未复制进调用方。
2. **text_grep 切换（src/tools/text.ts）**：删除旧 `parseGrepPattern`/`escapeRegex`，改用共享解析器；成功结果新增顶层 `patternMode: 'literal'|'regex'` 字段（含 0 命中成功）；字面量匹配改为纯子串比较（ignoreCase 走两侧小写），元字符零转义语义更纯粹；schema describe 与工具 description 同步改写（默认字面量 + 反斜杠路径免转义首例 + /…/ 启用正则 + flags 白名单）。search_content 未动（工单 03 承接对齐）。

**关键裁定：`/usr/bin` 判定与 ADR-0013 效果表示例的偏差** — ADR 效果表将 `/usr/bin` 标为字面量，但它与 EINVAL 示例 `/foo/q` 结构完全同形（`/词/字母段`），任何确定性规则无法区分二者、效果表内部不自洽。按本工单验收口径「末段全字母即 flags 形状、白名单外字母一律 EINVAL」（D6 ②：响错误优于哑回退，收敛原则只适用结构歧义场景）实现为 EINVAL，消息列明合法标志并含原串便于纠正。已在 pattern.ts 头注释与本纪要双处记录；如需改判请在工单 05 文案收口前提出。
