# text_grep 双向提示表

**Status:** resolved

**Blocked by:** 01

**构建内容：** 四类可疑误用在单文件搜索中各自触发针对性提示，把哑错误变成响错误：①字面量模式 0 命中且 pattern 含正则元字符 → 提示「像是正则但按字面量搜了」并给出包裹写法；②字面量模式 0 命中 → 拼写/大小写方向的通用提示；③命中数异常偏多且 pattern 形似正则 → 提示「疑似被当作正则」（兜住短字面量被误判的情形）；④正则模式 0 命中且 pattern 呈反斜杠路径样 → 提示反斜杠被当转义、建议改字面量。提示以成功响应的可选字段呈现，触发阈值集中于单一位置便于调参。

**验收标准：**

- [x] 四类场景各有触发/不触发的正反用例
- [x] 提示字段为可选增量字段，不触发时不占位
- [x] 「异常偏多」「形似正则」「元字符清单」等判据常量集中单一位置
- [x] 提示文案自解释且指向可行动作（改写成什么样式）

### 完成纪要（2026-08-24 · core-eng · 工单 02）

3. **text_grep 接线（src/tools/text.ts）**：成功响应条件性附加顶层可选字段 `hint: string`——以 payload 条件赋值实现「不触发不占位」（非 undefined 塞 null）；失败响应不受影响。

**四行提示表与文案（均指向可行动作）**

- ① 字面量+0命中+含元字符 → 列出命中的具体元字符 + 给出 `/…/` 包裹写法建议（建议串内斜杠自动转义保证自身合法）+ flags 提示
- ② 字面量+0命中 → 拼写/大小写检查指引 + ignoreCase:true 可行动作
- ③ 正则模式+命中异常偏多+形似正则 → 「疑似被当作正则」+ 去斜杠改字面量动作（兜住 /tmp/ 残余洞）
- ④ 正则模式+0命中+反斜杠路径样（盘符 C:\ 与 UNC \\ 双形状识别）→ 点破 `\U` 被当转义 + 去斜杠改字面量动作
