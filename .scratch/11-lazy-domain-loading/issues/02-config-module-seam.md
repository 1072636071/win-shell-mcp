# 配置模块 seam：环境变量解析收敛（WIN_SHELL_LAZY + 与 12 号共用）

**Status:** ready-for-agent

**Blocked by:** 无——可立即开始（需与 12 号工单协调模块创建方，见评论）

**构建内容：** 懒加载开关 `WIN_SHELL_LAZY=1` 有了唯一的解析入口。部署者通过环境变量启用懒模式时，开关读取只经过一个纯函数模块、不散落在 server 层；该模块是整批优化的公共配置 seam，`WIN_SHELL_TOOLS` 白名单（12 号工单）与 `WIN_SHELL_TRUNCATE`（15 号工单）随后并入同一处。由于不设环境变量时解析返回"全量模式"，既有客户端零影响。

**验收标准：**

- [x] 存在一个纯函数配置模块，初版承担环境变量解析：模块内**不**直接读 `process.env`，函数接受原始字符串（或 undefined）入参，返回解析结果
- [x] `WIN_SHELL_LAZY` 解析语义：`"1"` → 懒模式；缺省/空串/其他值 → 全量模式；`"0"`/`"true"` 等非 1 值明确落在全量模式，不产生歧义
- [x] 解析结果是纯函数、可注入伪造环境源测试（单测覆盖 `"1"`/缺省/空串/`"0"`/未知值等输入形态，不依赖真实 `process.env`）
- [x] 懒开关的唯一读取点收敛在配置模块或唯一调用点，server 层只消费解析结果，不直接碰 `process.env`
- [x] 接口与 12 号工单的白名单解析对齐（同模块、同为纯函数、同为"入参原始字符串 → 结果或错误"），便于后续变量并入
- [x] 全量模式回归：不设环境变量时 server 行为与现状逐字节一致

## 评论

（评论与对话历史追加于此，新内容置于最前。）

- 实施完成（团队任务 t2，eng-beta，终审 t9 通过）：唯一配置模块 `src/config/env.ts` 落地——导出 `ENV_WIN_SHELL_TOOLS`/`ENV_WIN_SHELL_LAZY` 常量、`parseToolsWhitelist(raw, canonicalToolNames)`（可辨识联合返回、未知条目含全部原文）、`parseLazyMode(raw)`（仅精确 "1"）；纯函数、零 import、不读 `process.env`、正名集合由调用方注入。26 个表驱动用例；与 12 号工单 01 合并交付，"只存在一个配置模块"约束满足。验收框已全部勾选。

- 协调点（关键）：12 号 PRD 决策 2 明确该配置模块由 12 号工单创建（初版接口 = 白名单解析），`WIN_SHELL_LAZY` 与 `WIN_SHELL_TRUNCATE` 为"随后并入同一模块"。11 号 PRD 决策 1 则说"若本工单先落地，则由本工单创建该模块"。两条 PRD 同时指向"只存在一个配置模块"。
- 落地规则：无论哪个工单先执行，**必须只创建一个配置模块**。若 12 号先创建了白名单解析骨架，本工单只做"并入 `WIN_SHELL_LAZY` 解析"而不再新建文件；若本工单（02）先落地，则创建骨架时接口必须与 12 号约定对齐（纯函数、入参原始字符串、模块内不读 `process.env`），并在 12 号工单评论区声明模块已由 02 创建、白名单解析直接并入。
- 阻塞说明：本工单不阻塞于 12（可先落地开关解析）；但 12 的白名单解析并入本模块时，若两者并行编辑同一文件存在合入冲突风险，需在提交前合并/协调。
