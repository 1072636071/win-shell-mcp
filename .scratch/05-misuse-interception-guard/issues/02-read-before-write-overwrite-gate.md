# 先读后写覆盖门槛

**Status:** ready-for-agent

**构建内容：** 「没看过内容就整体覆盖」被制度性堵死：server 进程内维护本会话已读路径集合（四种读类工具——单文件读取、连接读取、头部截取、尾部截取——成功读取即计入），写入工具的目标文件已存在且不在集合中时，覆盖被拒绝并提示先读；新建文件与追加写入不受限。进程重启导致集合清空的降级行为明确文档化（保护降级但不失效）。与指纹纠错完全独立，可并行开工。

**验收标准：**

- [ ] 未读过即覆盖已存在文件被拒，报错提示先用读类工具查看
- [ ] 四种读类工具的成功读取均能解锁后续覆盖
- [ ] 新建文件创建不受限
- [ ] 追加写入不受限
- [ ] 集合随进程重启清空的降级行为有测试佐证或在文档中明确声明
- [ ] 拒绝遵循统一输出契约的错误码与消息结构
