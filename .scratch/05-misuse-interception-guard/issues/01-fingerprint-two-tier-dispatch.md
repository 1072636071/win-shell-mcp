# 参数指纹纠错双档制（分发层单点）

**Status:** ready-for-agent

**构建内容：** 用错工具有解药了：在 server 分发层的参数校验唯一收口处增加指纹检查——调用的未知参数恰好是另一个已注册工具的特征参数时，拒绝执行并在报错里直接指名正确工具（多工具候选时按加权排序：缺失必选参数归属 > 命中个数 > 单工具唯一性，仍并列则全部列出）；与其余所有工具都不相关的未知参数不打扰，调用照常成功但响应顶层附提醒数组。全部注册工具自动生效，包括黑盒执行通道的参数层。真实事故原型（向写入类工具传编辑特征参数导致整文件覆盖）在此类调用发生时被当场拦下。

**验收标准：**

- [ ] 混型调用被拒且报错消息指名正确工具（事故原型场景复现断言）
- [ ] 多义场景有对照组断言加权排序与并列全列行为
- [ ] 无关未知参数放行且响应携带提醒数组；纯净调用不含提醒字段
- [ ] 黑盒执行通道工具的参数层冒烟覆盖
- [ ] 错误遵循统一输出契约的标准错误码与消息结构
- [ ] 提醒数组作为可选增量字段记入 README 输出契约说明
