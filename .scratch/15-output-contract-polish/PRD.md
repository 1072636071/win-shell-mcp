# PRD / Spec — 输出契约细节打磨

Status: ready-for-agent
日期：2026-08-25
来源：PRD-07（`.scratch/07-token-optimization/PRD.md`）优化点 P2-2
优先级：P2
关联：ADR-0003（极简输出）、0003-output-contract-and-dedup（统一错误契约、截断默认 2000）、memorial 007（主动充分返回）

## 问题陈述

输出契约在三处仍有打磨空间，调查确认：

1. **错误信息无 hint**：统一错误形态是 `{ ok: false, error: { code, message } }`，没有下一步提示字段。而成功输出侧已有成熟的 hint 实践（`text_grep`/`search_content`/`text_replace` 按规则生成可选 `hint`）。失败路径恰恰是 AI 最需要"下一步干什么"的时刻。
2. **截断阈值写死**：`DEFAULT_TRUNCATE_LIMIT = 2000` 是编译期常量，token 敏感场景（小上下文模型、长会话尾段）无法调低；工具级 `maxLen` 参数只有个别工具有（`fs_read`/`env_get`）。
3. **空结果形态未统一审计**：`fs_list` 空目录返回 `{ ok: true, entries: [] }` 已极简，但其余工具的空结果形态从未系统审计，可能残留装饰性字段。

## 解决方案

给统一错误契约增加可选 `hint` 字段（克制使用：只在有真实可操作信息时出现、限长、不教 AI 已知常识）；新增 `WIN_SHELL_TRUNCATE` 环境变量调整全局截断默认值（优先级：工具级参数 > 环境变量 > 常量）；对全部工具的空结果形态做一次审计收敛，只删装饰、不动判别字段（memorial 007 的主动充分返回原则仍然有效）。

## 用户故事

1. 作为调用失败的 AI，我想要错误在确有可操作信息时附一句短提示（如参数范围越界时给出合法范围），以便下一步动作明确。
2. 作为 AI，我想要错误提示保持克制——没有真实增量信息时不出现 `hint` 字段，且绝不教我本来就会的事（"你可以用 fs_list 看看目录"这类不写），以便错误路径不产生噪音。
3. 作为 AI，我想要 `hint` 不超过一句话（限长 50 字符量级），以便错误体量的增长被钉死在每次 20-30 token 以内。
4. 作为部署者，我想要用 `WIN_SHELL_TRUNCATE=800` 压低全局截断阈值，以便小上下文场景下长内容默认回得更短。
5. 作为部署者，我想要不设该变量时截断行为与现状完全一致（2000），以便默认零变化。
6. 作为 AI，我想要工具级 `maxLen` 参数仍然优先于环境变量，以便单次调用的精确控制不被全局设置覆盖。
7. 作为 AI，我想要所有工具的空结果都是最小形态（只有判别所必需的字段），以便"没有命中"这个结论以最便宜的代价获得。
8. 作为 AI，我想要空结果中的判别字段被保留——如 `text_grep` 空命中的 `count: 0, truncated: false, patternMode`，以便我能区分"真的没有"与"截断/模式误解导致的看似没有"（memorial 007 主动充分返回在空结果场景的体现）。
9. 作为维护者，我想要 `hint` 的生成标准写成明确规则（何为可操作、长度上限、无规则触发不占位），以便后续工具照章办事。
10. 作为维护者，我想要截断阈值的环境变量解析并入 12 号工单创建的配置模块，以便 env 读取仍然只有一处。
11. 作为维护者，我想要空结果审计的逐项结论记录在本工单评论区，以便"删了什么、留了什么、为什么"可追溯。

## 实现决策

1. **错误契约扩展**：`error` 对象增加可选 `hint?: string`。生成标准：(a) 仅当存在具体的、当前错误专属的可操作信息（合法范围、期望格式、冲突位置）；(b) 不重复 message 已含内容；(c) 不教通用常识；(d) 长度 ≤ 50 字符；(e) 无规则触发则字段整体缺省，不出现空串占位。契约构造函数增加可选第三参数，缺省行为与现状逐字节一致。
2. **首批应用点（克制清单）**：
   - 调用被白名单裁掉的工具（12 号工单的错误区分）：hint 说明如何查看当前暴露范围；
   - 参数越界类 `EINVAL`（如行/字节范围互斥规则违反）：hint 给出合法组合；
   - 其余错误码（`ENOENT`/`GIT_FAIL` 等）默认不加 hint——路径不存在时 AI 自己知道下一步，加了就是噪音。
3. **截断环境变量**：`WIN_SHELL_TRUNCATE`，正整数，缺省 2000；解析并入配置模块（12 号工单创建），非法值（非正整数）启动报错、fail-fast，与白名单的严格风格一致。生效优先级：工具级 `maxLen`/同类参数 > 环境变量 > 常量 2000。实现上，截断函数的默认值参数从常量改为读取配置后的默认值，各调用点语义不变。`git` 域内部对 stderr 的 500 字符内联截断保持原样（那是错误面降噪，不属于内容截断契约）。
4. **空结果审计与收敛**：对全部输出列表型结果的工具逐一核对空输入时的返回形态。判定标准：字段是否帮助 AI 判断"空"的性质（真没有 / 被截断 / 模式误解）——帮助则留（判别字段），不帮助则删（装饰字段）。已知基线：`fs_list` 空返回 `{ ok: true, entries: [] }`（达标，不动）；`text_grep` 空返回保留 `count`/`truncated`/`patternMode`（均为判别字段，不动）。审计逐项结论写入评论区；凡涉及删除既有输出字段的，按 ADR-0007 的 0.x 窗口集中处理并在 CHANGELOG 记录。
5. **成功侧既有 hint 不动**：`buildSearchHint` 的四条规则与现有应用点维持原状，本工单只把 hint 概念扩展到错误侧。

## 测试决策

1. **好测试的标准**：契约形态与优先级是可观察事实，全部可测；措辞细节（hint 具体文案）不锁，只锁"存在性 + 长度 + 缺省行为"。
2. **seam**：`src/contract/output.ts` 的契约函数（既有契约层测试先例 `tests/contract/output.test.ts`）；配置模块纯函数（12 号工单）；`callTool()`（行为面）。
3. **新增用例**：
   - 契约：带 `hint` 的失败输出形态正确；不带时与现状逐字节一致；`hint` 超长在构造层截断或报错（二选一，实施时定，测试钉死所选行为）。
   - 配置模块：`WIN_SHELL_TRUNCATE` 解析（合法/缺省/非法值）。
   - 截断优先级：注入不同默认值后，工具级参数 > 环境变量 > 常量的三层关系（用最小工具如 `fs_read` 验证）。
   - 空结果：审计中被改动形态的工具各补一条空输入断言；未改动的（`fs_list`/`text_grep`）已有断言保持绿即为回归。
   - 白名单错误提示与 12 号工单的用例合并维护，避免两处重复。
4. **先例**：`tests/contract/output.test.ts`（截断与形态断言，含精确字符串断言先例）、`tests/contract/errors.test.ts`（表驱动）。

## 超出范围

- 不扩写成功侧 `buildSearchHint` 的规则。
- 不引入错误分级/重试标志（`retryable` 之类的字段）——没有真实需求前不加词汇。
- 不改截断的标记格式（`...[truncated, N more chars]` 维持，AI 已熟悉该约定）。
- 不做运行期动态调阈值（重启生效即可）。

## 补充说明

- 收益估算：每次错误/空结果省 20-50 token；截断可调后，小上下文场景的长内容开销结构性下降。
- 与 memorial 007 的边界：本工单删的是装饰，不是判别信息——"主动充分返回判别信息"的原则在空结果收敛中显式保留（用户故事 8），两原则的冲突点以"字段是否改变 AI 决策"裁决。
- 兼容性：`hint` 为可选新增字段（非破坏）；空结果删字段若发生则属破坏性，走 0.x 窗口 + CHANGELOG。
- 预估工作量：3 小时。
