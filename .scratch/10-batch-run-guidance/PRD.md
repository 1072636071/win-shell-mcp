# PRD / Spec — batch_run description 主动引导使用

Status: ready-for-agent
日期：2026-08-25
来源：PRD-07（`.scratch/07-token-optimization/PRD.md`）优化点 P0-3
优先级：P0
关联：ADR-0015（batch_run）、ADR-0003（极简输出）

## 问题陈述

`batch_run` 已实现，但它省 token 的前提是 AI 真的在用它。当前 description 只描述机制（串行、断言、引用模板），没有任何"什么场景该用我"的引导——AI 读到一个普通工具，多步任务仍会习惯性地逐轮调用，token 节省落空。工具描述是 AI 决策的第一触点，引导语必须写在这里，而不是指望 AI 自己发现。

## 解决方案

重写 `batch_run` 的 description：以"多步操作请优先用 batch_run 一次完成"的引导开篇，附典型场景示例（读文件→定位→替换→写回），再给出最简机制要点（steps/assert/refs 语法），机制细节外移给速查表与预设文档。与 08 号工单（描述精简）合并为同一次改写，避免同一文本两次变更。

## 用户故事

1. 作为接到多步任务的 AI，我想要 `batch_run` 的描述第一句就告诉我"多步操作优先用它一次完成，避免多轮往返"，以便我在规划阶段就选对形态，而不是跑完三轮才意识到有 batch。
2. 作为 AI，我想要描述里有一个典型场景示例（如"读文件→grep 定位→替换→写回，一次完成"），以便快速判断手头任务是否适合批量。
3. 作为 AI，我想要描述给出引用语法的最小样例（`{{stepId.output.path}}`）与断言的存在（10 种操作符），以便不查文档就能编出第一个可用的 batch。
4. 作为 AI，我想要机制细节（引用类型保持规则、断言逐条归因、短路语义）指向预设文档与速查表，以便描述保持精短而深究有去处。
5. 作为 AI，我想要描述同时说明默认输出极简、调试详情传 `verbose: true`，以便对返回形态有正确预期（与 09 号工单协同）。
6. 作为维护者，我想要这次改写与 08 号工单的描述精简是同一次编辑，以便同一文本不发生两轮变更、不互相覆盖。
7. 作为维护者，我想要改写后的描述仍在 08 号工单的预算内，以便引导语不成为膨胀的例外。
8. 作为维护者，我想要描述中的事实（操作符 10 种、引用语法、默认极简）与实现逐项核对，以便不再出现"9 种操作符"式的错误。

## 实现决策

1. **描述结构（四段式，压进 08 号工单预算）**：
   - 引导：多步操作请优先用 `batch_run` 一次完成，避免多轮往返。
   - 场景：典型如"读文件→grep 定位→替换→写回"。
   - 机制要点：`steps: [{ id?, tool, args, assert? }]` 串行短路；断言 10 种操作符（eq/neq/gt/gte/lt/lte/in/re/truthy/falsy）；步骤间引用 `{{stepId.output.path}}`。
   - 输出预期：默认只返回 `{ ok, summary }`（失败附 `failedStep`），详情传 `verbose: true`；更多场景模板见 `docs/batch-presets/`（16 号工单落地后生效的指针）。
2. **合并实施**：本工单与 08 号工单对 `batch_run` description 的修改合并为一次编辑；实施顺序上本工单跟随 08，验收可并入 08 的护栏。
3. **事实核对清单**（改写时逐项对照实现）：操作符恰为 10 种；引用模式为 `{{stepId.output.path}}`，整串单引用保原类型；短路覆盖四类失败（未知工具、参数非法、handler 失败、断言不满足）；默认输出形态以 09 号工单落地后的为准。
4. **不改行为**：本工单只改 description 文本，不动 handler、schema、annotations。

## 测试决策

1. **好测试的标准**：引导语义是外部可观察事实（description 是 ListTools 输出的一部分），可以用最小关键词断言钉住"引导存在"，但不锁死全文措辞。
2. **seam**：`listTools()`（既有）。
3. **断言**：`batch_run` 的 description 包含引导关键词（"优先"与"一次"）与场景要素；长度满足 08 号工单的预算护栏。护栏测试与 08 号工单同址（元数据护栏），本工单只追加这组断言。
4. **先例**：现有测试对 description 仅有 `length > 0` 断言（`tests/server.test.ts`）；本工单把"关键语义存在"提升为可断言项，但保持克制（只断言引导语义，不快照全文）。

## 超出范围

- 不在其他工具描述里交叉推荐 `batch_run`（一处引导足够，避免到处刷屏）。
- 不做 batch 预设文档本体（16 号工单），本工单只预留指针。
- 不做运行时的使用统计/提示（server 不观察 AI 行为）。

## 补充说明

- 预估收益：AI 多步任务的回合数下降；每减少一轮往返，省下一次 ListTools 固定开销之外的一整轮请求/响应。
- 风险：无行为风险；唯一注意点是引导语占用预算额度，已与 08 号工单约定同一文本一次成型。
- 预估工作量：30 分钟（并入 08 实施）。
