# PRD / Spec — 破坏性操作保护（回收站 + 审计日志）

- 状态：ready-for-agent
- 域：fs/text/archive/net/shell_exec + 新增保护域（fs_restore / fs_trash_list）
- 类型：task
- 来源：memorial 002-destructive-op-log-recovery（D1-D15，docs/memorial/archived/002-destructive-op-log-recovery/context.md）；ADR-0008（回收站型保护）、ADR-0009（例外与配置）

## 问题陈述

win-shell-mcp 定位「无沙箱全权限、与裸 shell 等价」（ADR-0002），破坏性操作（删除、覆盖、移动覆盖等）直接生效：无日志、无备份、无撤销。AI 误删文件、覆盖源码后无任何挽回手段；出错后也无法追溯「哪个 AI、何时、用哪个工具、动了什么」。用户诉求：所有破坏性操作记录日志、日志默认 `D:\log`、可通过环境变量配置、保证可恢复。

## 解决方案

引入**回收站型破坏操作保护**（ADR-0008/0009）：

- **默认关闭**：未开启时行为与现状完全一致（零变化）。
- **开启方式**：环境变量 `WIN_SHELL_PROTECT=1`（进程级，启动时读取）。
- **保护流程**：破坏操作执行前，将目标原数据备份到 `<日志根>/backup/<操作ID>/`（含 meta.json），然后执行原操作；每个破坏操作追加一行审计记录到 `logs/operations.jsonl`。
- **还原通道**：新增 `fs_trash_list`（列回收站批次）与 `fs_restore`（按操作 ID 还原整批，原位置冲突则报错）。
- **两类例外直接真删不备份**：低价值名单（内置 + `WIN_SHELL_LOWVALUE_LIST` 追加）；大小阈值（`WIN_SHELL_BACKUP_MAX_BYTES`，默认 1GB）。
- **失败兜底**：备份失败则破坏操作中止，返回 AI 可理解的语义化错误（原因 + 可行出路）。
- **黑盒审计**：shell_exec/run_command 不备份，但审计日志记录原始命令文本。

## 实现决策

### 配置（D15）

- 四个环境变量，启动时读取一次，进程级生效：
  - `WIN_SHELL_PROTECT` — 置 `1` 开启（默认空 = 关闭）
  - `WIN_SHELL_LOG_DIR` — 日志根（默认 `D:\log`）
  - `WIN_SHELL_LOWVALUE_LIST` — 逗号分隔，**追加**到内置名单（内置：node_modules/.git/dist/build/.cache/__pycache__/target）
  - `WIN_SHELL_BACKUP_MAX_BYTES` — 大小阈值（默认 1GB）

### 主 seam：分发点包装 + 声明式元数据（已与用户确认）

- 工具接口新增可选 `protection` 元数据：声明破坏类型与目标路径参数——`delete`（删除目标：path 参数）、`overwrite`（覆盖目标：目标路径参数）、`audit-only`（黑盒，仅记命令文本）。7 个破坏工具声明式标注，**handler 零改动**。
- 唯一包装点：工具分发（callTool）在保护开启时对带 `protection` 元数据的工具执行「保护流程 → 原 handler → 补记结果」；关闭时直接透传原 handler。
- 保护流程内部次序：判定开启 → 判定例外（低价值名单命中 / 体积超阈值）→ 未命中例外则备份批次 → 执行原 handler → 写审计行（含结果）→ 返回结果（附操作 ID）。

### 保护模块（新，独立于工具域）

- **备份批次**：`<日志根>/backup/<操作ID>/`，操作 ID 为时间戳 + 序号 + 工具名；批次内为被破坏目标的完整拷贝（目录递归）+ `meta.json`（原路径/工具/参数/时间/操作 ID/结果）。
- **审计流**：`<日志根>/logs/operations.jsonl`，每个破坏操作一行 JSON（含黑盒命令文本、例外命中标记、跳过备份原因）。
- **判定**：低价值名单（内置 + 追加，任意层级 basename 匹配）；大小阈值（目录递归累计体积）。
- **还原**：`fs_restore` 按操作 ID 读取 meta.json → 校验原位置冲突 → 拷回并移除批次；`fs_trash_list` 扫描 backup 目录列出批次。
- **错误契约**：新增 `EBACKUP` 类错误码；错误消息为 AI 可理解的语义化文案（原因 + 出路），遵循现有极简错误映射。

### 新工具

- `fs_restore`（输入：操作 ID）— 还原整批；冲突报错。
- `fs_trash_list`（无输入或可选过滤）— 列批次：操作 ID/原路径/时间/大小。

### 兼容性（ADR-0007）

- 处于发布前窗口：`fs_restore`/`fs_trash_list` 为新工具；破坏工具不新增必填参数；开启保护后的返回可在既有字段之外**追加** `backupId` 等可选字段，默认（未开启）行为不变。

## 测试决策

- **好测试的标准**：只测外部行为——备份批次出现/不出现、还原成功/冲突、审计行内容、开启/关闭行为差异；不测内部函数调用次序。
- **保护模块单测**：配置读取（环境变量注入：开启/关闭/自定义目录/追加名单/阈值）、低价值名单匹配（任意层级、内置 + 追加、覆盖类命中）、体积阈值判定、备份批次结构（meta.json 字段、操作 ID 唯一性）、审计流 JSONL 行格式、restore 冲突与成功、批次移除。
- **分发包装集成测**：走完整工具调用链（server 测试既有模式）——开启时 fs_rm/fs_write/fs_mv/fs_cp/text_replace/archive_extract/net_download 触发备份与审计；关闭时与现状逐字节一致；shell_exec 审计命令文本；备份失败时破坏操作不执行且返回语义化错误。
- **测试环境**：所有备份/审计落盘用临时目录（现有 fs 测试同款临时目录模式），不触碰真实 `D:\log`。

## 超出范围

- git 域保护（checkout 丢弃工作区等）——git 自有 reflog/stash 机制，不纳入本批次。
- 完整 undo 链 / 操作序列回滚（ADR-0008 已否决）。
- 回收站自动清理（TTL / 容量上限）——不自动清理，由用户自行管理。
- 配置文件通道（JSON 等）——全部配置走环境变量（ADR-0009 已决）。
- 每调用级真删参数（如 permanent: true）——行为由名单与阈值规则决定。
- 保护开启时对非破坏工具的性能影响优化。

## 补充说明

- 备份实现以 copy 为主（跨盘安全），同盘场景的 rename 优化留给实施工单自行权衡。
- 开启保护后所有破坏操作（含还原操作 fs_restore 本身对目标位置的写入）均在审计流中留痕，保证审计链完整。
- 大小阈值与低价值名单是两个正交维度：名单 = 低价值语义，阈值 = 成本语义；命中任一即跳过备份，审计行中记录跳过原因。
