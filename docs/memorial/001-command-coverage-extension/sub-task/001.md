### 1. 缺失命令清单（问题 a）

判定依据：上表 46 个工具 name 全集 + 对 `src/` 的关键词检索（`zip`/`tar`/`base64`/`clipboard`/`watch`/`netstat` 均无能力命中；`node:crypto` 全 src 0 命中；`symlink` 命中仅为"类型检测"、`hash` 命中均为 git commit hash，非文件哈希）。

#### P0（AI 日常高频，当前只能用 shell_exec 兜底）

**M1. 下载到文件（net_download / net_get 加 saveTo）— P0**
- **事实**：net_get 输入仅 url/timeoutMs/verbose（src/tools/net.ts:186-198），返回 body 为截断字符串（src/tools/net.ts:153-157；DEFAULT_TRUNCATE_LIMIT=2000，src/contract/output.ts:36），无"写入文件"参数；net_post 同样只返回 body 文本（src/tools/net.ts:313-323）。
- **分析**：下载依赖包/字体/二进制到磁盘是高频操作；且 body 截断 2000 字符意味着即便走 net_get 也拿不到完整内容，当前必须 shell_exec 调 curl / Invoke-WebRequest。

**M2. 归档压缩/解压（archive：tar/zip）— P0**
- **事实**：46 工具中无归档能力（关键词检索无命中）；Windows 自带 tar.exe 与 Compress-Archive 可用。
- **分析**：打包产物、解压下载的依赖/资源是开发会话高频操作，当前只能 shell_exec。

#### P1（中频）

**M3. git 子命令缺口：git_checkout / git_push / git_pull / git_clone / git_stash — P1**
- **事实**：git 域现仅 status/log/branch/diff/add/commit 六个（src/tools/git.ts:248, 340, 429, 495, 547, 608），无 checkout/push/pull/clone/stash。
- **分析**：切分支、推送、拉取、克隆、暂存是 git 工作流主干，缺任何一个都会把 AI 推回 shell_exec。属八域内补全，按 D1 不设新域闸门。

**M4. 文件哈希（file_hash：sha256/md5）— P1**
- **事实**：全 src 无 node:crypto 导入（检索 0 命中），无哈希工具。
- **分析**：校验下载完整性、去重、缓存 key 属中频需求。

**M5. 目录磁盘占用（du / dir_size）— P1**
- **事实**：system_disk 只返回文件系统级 total/free/used（src/tools/system.ts:144-150, 310-331），无目录级累计大小。
- **分析**："哪个目录占空间大"（node_modules、构建产物清理）是中频诊断需求。

**M6. 时间/日期（system_date）— P1**
- **事实**：system_info 返回字段为 os/arch/platform/hostname/cwd/node，verbose 增加 uptime/loadavg/cpus/mem 等（src/tools/system.ts:93-121），不含当前日期时间。
- **分析**：AI 生成带时间戳的文件名、日志、提交信息需要当前时间；实现成本极小。亦可作为 system_info 扩展落地（见 E-25，二选一）。

**M7. 端口监听查询（net_listen / netstat）— P1**
- **事实**：net_tcp 只做"能否连上 host:port"探测（src/tools/net.ts:493-548），无"本端口被哪个进程监听"。
- **分析**：调试"端口占用"是中频场景，当前只能 shell_exec netstat。

**M8. JSON 处理（json_get：jq-lite）— P1**
- **事实**：无 JSON 专用工具；text_grep 按行匹配（src/tools/text.ts:91-146），无法按 JSON 路径取值。
- **分析**：解析 package.json、CI 输出、API 响应字段是中频操作。

### 2. 现有命令能力缺口/拓展点清单（问题 b）

按域列出；每条含缺口、证据、建议、优先级。

#### net 域

**E-01. net_get / net_post 缺自定义请求头 — P1**
- **事实**：net_get schema 仅 url/timeoutMs/verbose（src/tools/net.ts:186-198）；net_post 仅在 json=true 时自动加 Content-Type（src/tools/net.ts:300-303），两者均无 headers 参数。
- **分析**：带 Authorization/API key 的接口调用是 AI 高频场景。
- **建议**：两工具增加 `headers?: Record<string,string>`。

**E-02. net_get 无"保存到文件" — P1（与 M1 同一缺口，二选一落地）**
- **事实**：同 M1（src/tools/net.ts:153-167, 186-198）。
- **建议**：net_get 加 `saveTo?: string`（body 落盘，返回 {saved, bytes}），或单列 M1 新命令。

**E-03. net_post body 仅字符串、无 PUT/DELETE — P2**
- **事实**：body 为 string（src/tools/net.ts:253）；PUT/DELETE 为 Phase 2A 有意裁剪（src/tools/net.ts:9-12 注释）。
- **分析**：按 D2，PUT/DELETE 低频，维持兜底即可。

#### git 域

**E-04. git_diff 无目标 ref — P1**
- **事实**：git_diff 仅支持 staged（--cached）与 path 限制（src/tools/git.ts:440-445, 471-475），无 against（commit/分支/HEAD~1）。
- **分析**："和上次提交比""和 main 比"是高频 diff 场景。
- **建议**：加 `against?: string`（透传 `git diff <ref>`）。

**E-05. git_log 无作者/分支/文件过滤 — P2**
- **事实**：schema 仅 cwd/limit/verbose（src/tools/git.ts:259-263）。

**E-06. git_branch 仅列本地分支 — P2**
- **事实**：`git branch --list` 只列本地分支（src/tools/git.ts:403-406）。

#### search 域

**E-07. search_content 仅子串匹配、无正则 — P1**
- **事实**：pattern 描述为"字符串子串匹配"（src/tools/search.ts:249），实现用 `includes`（src/tools/search.ts:306, 325）。
- **分析**：跨文件正则搜索是 AI 最高频检索形态之一；text_grep 有正则但仅单文件（src/tools/text.ts:57-58），两者互补后仍有空洞。
- **建议**：pattern 支持 /正则/ 形式（与 text_grep 对齐，src/tools/text.ts:77-89）。

**E-08. search_content 无上下文行 — P2**
- **事实**：仅返回命中行（src/tools/search.ts:326）。
- **分析**：命中后可对单文件调 text_grep（context 参数，src/tools/text.ts:61）拼接上下文，故降 P2。

**E-09. search_glob 不匹配目录 — P2**
- **事实**：listFiles 只收集 `isFile()` 条目（src/tools/search.ts:120）。

#### process 域

**E-10. process_list 无命令行/CPU，filter 大小写敏感 — P1**
- **事实**：条目仅 pid/name，verbose 加 memory（src/tools/process.ts:48-56）；filter 为大小写敏感 includes（src/tools/process.ts:34, 227-228）。
- **分析**：AI 查/杀进程前几乎总要先看"它到底在跑什么"（cmdline）；Windows 进程名大小写不敏感，filter 敏感会漏匹配。
- **建议**：verbose 增加 cmdline；filter 改大小写不敏感。

**E-11. process_kill 无进程树终止 — P1**
- **事实**：Windows 路径 taskkill 仅 /PID（force 时加 /F），无 /T（src/tools/process.ts:296-302）。
- **分析**：杀 dev server/构建进程时子进程残留（node 子进程、watcher）是高频痛点。
- **建议**：加 `tree?: boolean`（Windows /T，unix 杀进程组）。

#### 执行域（shell_exec / run_command）

**E-12. shell_exec Windows 固定 cmd.exe，无 PowerShell 选项 — P1**
- **事实**：shell 硬编码 `cmd.exe /c`（src/tools/shell_exec.ts:88-89）。
- **分析**：PowerShell 是 Windows 默认现代 shell，管道/对象能力远强于 cmd；AI 写 shell 片段时大量习惯 PS 语法。
- **建议**：加 `shell?: 'auto'|'cmd'|'powershell'`（unix 侧对应 'sh'|'bash'）。

**E-13. shell_exec / run_command 无 stdin 输入 — P1**
- **事实**：shell_exec stdio[0]='ignore'（src/tools/shell_exec.ts:108）；run_command 无 input 参数（src/tools/run_command.ts:103-117）。
- **分析**：向命令喂数据（`echo x | cmd`、交互式程序）是中频需求。
- **建议**：加 `stdin?: string`。

**E-14. shell_exec 无后台执行 — P2**
- **分析**：MCP 单次调用模型下 timeout 可覆盖多数长任务；真后台需要任务管理面，超出本次范围。

#### fs 域

**E-15. fs_list 无排序、无过滤 — P1**
- **事实**：schema 仅 path/verbose/recursive（src/tools/fs_read.ts:45-52）；非递归直接返回 readdir 原序（src/tools/fs_read.ts:143-160）；verbose 条目仅 name/type/size，无 mtime（src/tools/fs_read.ts:54-59）。
- **分析**：AI 期望 ls 稳定有序以便判断；"只看 *.ts""只看目录"是高频过滤。
- **建议**：加 `sortBy?: 'name'|'size'|'mtime'`、glob/类型过滤参数，verbose 补 mtime。

**E-16. fs_write 父目录必须已存在，无自动 mkdir — P1**
- **事实**：父目录不存在直接 ENOENT（src/tools/fs_write.ts:97-109）。
- **分析**：AI 写新路径时"顺手建目录"是高频动作（等价 shell 的 `mkdir -p && cat >`）。
- **建议**：加 `mkdir?: boolean`（默认 false 保持现状）。

**E-17. fs_mv 不覆盖、不能"移入目录" — P1**
- **事实**：dest 已存在即 EINVAL（src/tools/fs_write.ts:53, 279-288）；dest 为目录时 fs.rename 语义不适配（src/tools/fs_write.ts:290）。
- **分析**：mv 覆盖与 `mv a b/` 是高频用法。
- **建议**：加 `overwrite?: boolean`；dest 为目录时语义化为移入该目录。

**E-18. fs_read 整文件读入内存 — P2**
- **事实**：先 readFile 全量再切行（src/tools/fs_read.ts:217-229）。
- **分析**：大文件分页内存非最优；当前体量可接受，流式读取留后续。

**E-19. fs_read 与 cat 职责重叠、区间语义不一致 — P2**
- **事实**：fs_read 行范围 start/end 为"含 start 不含 end"（src/tools/fs_read.ts:185-186）；cat 为 startLine/endLine"1-based 含"并另有字节范围（src/tools/text_cat.ts:29-32）。
- **分析**：功能大面积重叠且区间语义不一致，AI 选错工具概率不低；建议文档层面明确分工或统一区间语义。

**E-20. fs_rm 无回收站 / fs_stat 无权限属主 — P2**
- **事实**：fs_rm 直接删除（src/tools/fs_write.ts:164-215）；fs_stat 返回 type/size/mtime/birthtime（src/tools/fs_read.ts:258-260, 287-292）。
- **分析**：Windows 下权限/属主意义弱，回收站属低频。

#### text 域

**E-21. text_replace 写回恒为 utf-8，可能改变原文件编码 — P1（正确性）**
- **事实**：读取走自动检测 GBK/UTF-8（src/tools/text.ts:36-45），写回硬编码 utf-8（src/tools/text.ts:482）。
- **分析**：GBK 文件经 text_replace 原地写回后编码被静默改为 UTF-8，对下游工具是隐性破坏；属正确性缺口而非便利缺口。
- **建议**：写回沿用源编码，或加 `encoding` 参数。

**E-22. text_diff 是朴素逐行对比，非真 diff — P1（正确性）**
- **事实**：lineDiff 按索引逐行配对（src/tools/text.ts:276-290），无 LCS/Myers；输出声称 unified diff 格式（src/tools/text.ts:292-373）。
- **分析**：任一文件插入一行后其后所有行全部被标记为 del+add，hunk 失真，AI 据此判断"改了什么"会出错。
- **建议**：引入真正行级 diff 算法，或至少降级描述为"逐行对比"。

**E-23. text_grep 单文件、context 无前后分离 — P2**
- **事实**：path 为单文件（src/tools/text.ts:57-58）；context 为前后各 N 行（src/tools/text.ts:61, 126-133）。
- **分析**：跨文件由 search_content 承接（其正则缺口见 E-07）。

**E-24. text_head / text_tail 无字节计数 — P2**
- **事实**：仅 lines 参数（src/tools/text.ts:157-160, 190-193）。

#### system 域

**E-25. system_info 无当前日期时间 — P1（与 M6 同一缺口，二选一落地）**
- **事实**：同 M6（src/tools/system.ts:93-121）。
- **建议**：system_info verbose 加 `time`（ISO 8601），或单列 M6 新命令。

**E-26. system_memory swap 仅 Linux — P2**
- **事实**：readSwapInfo 非 linux 直接返回空（src/tools/system.ts:384-403）。

**E-27. system_disk 无目录级占用 — P2（与 M5 同一缺口，二选一落地）**
- **事实**：同 M5（src/tools/system.ts:310-331）。

#### pkg 域

**E-28. pkg_detect 只给布尔、丢弃版本号 — P2**
- **事实**：用 `--version` 探测但仅保留 exitCode（src/tools/pkg.ts:73-100）。

**E-29. pkg_run 无 env 参数（shell_exec 有）— P2**
- **事实**：pkg_run schema 无 env（src/tools/pkg.ts:143-160）；shell_exec 有 env（src/tools/shell_exec.ts:42-45）。

#### env 域

**E-30. env_set 仅进程级、无持久化 — P2**
- **事实**：直接写 process.env（src/tools/env.ts:118），描述自称"对后续会话生效"（src/tools/env.ts:126）。
- **分析**：MCP 进程生命周期内有效已覆盖多数场景；注册表级持久化是独立决策，留兜底。

**E-31. env_get 全量返回无过滤/截断 — P2**
- **事实**：name 省略时返回全部 vars，无 filter 参数且未走 truncate（src/tools/env.ts:61-68）。
- **分析**：env 较多的会话（CI）全量返回 token 成本偏高，与极简输出原则（CONTEXT.md:15）有张力。

#### core / net 其它

**E-32. ping 实为 TCP 探测（非 ICMP）— P2**
- **事实**：模块注释自述（src/tools/net_ping.ts:4-6）；probeOnce 用 TCP 连接测时（src/tools/net_ping.ts:95-130）。
- **分析**：已如实标注，保持现状即可。

**E-33. net_dns 无 SRV/NS 记录类型 — P2**
- **事实**：记录类型枚举仅 A/AAAA/CNAME/MX/TXT（src/tools/net.ts:338）。

### 3. 优先级汇总

- **P0（2 项）**：M1 下载到文件、M2 归档压缩/解压。
- **P1 缺失（6 项）**：M3 git 子命令缺口、M4 文件哈希、M5 du、M6 时间/日期、M7 端口监听、M8 JSON 处理。
- **P1 拓展（14 项）**：E-01（net 自定义头）、E-02（saveTo）、E-04（git_diff 目标 ref）、E-07（search_content 正则）、E-10（cmdline）、E-11（进程树）、E-12（PowerShell 选项）、E-13（stdin）、E-15（fs_list 排序过滤）、E-16（fs_write 自动 mkdir）、E-17（fs_mv 覆盖/移入目录）、E-21（text_replace 编码保持）、E-22（text_diff 真 diff）、E-25（当前时间）。
- **P2（25 项）**：M9–M14；E-03、E-05、E-06、E-08、E-09、E-14、E-18、E-19、E-20、E-23、E-24、E-26–E-33。
- **去重说明**：M1/E-02、M5/E-27、M6/E-25 为同一缺口的"新增命令 vs 现有工具扩展"两种落地形态，各自落地其一即可消除该缺口。
