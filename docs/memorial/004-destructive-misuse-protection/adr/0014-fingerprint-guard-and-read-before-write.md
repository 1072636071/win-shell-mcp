# ADR-0014: 参数指纹纠错与先读后写——AI 误用拦截层

状态：Accepted（memorial 内草案；结项时询问同步 docs/adr/）

日期：2026-08-24

来源：memorial 004-destructive-misuse-protection（D3–D6）

## 上下文

- 事故：AI 调用方想做定向编辑，实际以 write 工具发出混型调用（content 合法 + edit 的 old_string/new_string 杂质参数），zod 非 strict 校验静默剥离未知参数后照常执行，整个 CONTEXT.md 被覆盖销毁（靠会话内曾读过原文才恢复）。
- 结构性原因：`src/server.ts:65` 的 safeParse 是全项目唯一参数校验收口；zod 默认非 strict，未知参数被剥离而非拒绝；fs_write 对已存在文件无任何前置条件。
- 定位约束：本项目为「确定性命令」（ADR-0002/0007），拦截必须可预测、报错必须自解释可行动；0.x 发布前窗口允许行为变更。

## 决策

1. **双档制指纹纠错（dispatch 单点实现）**：在 server.ts 参数校验收口处增加未知参数检查：
   - 未知参数名命中任一其他已注册工具的 schema 参数名 → **EINVAL**，报错指路正确工具（例：「old_string 属于 edit 工具——你可能想调用的是 edit」）。多义时加权：缺失必选参数归属 > 命中参数个数 > 参数唯一性；仍并列则全部列出候选。
   - 其余未知参数 → 响应附 `warnings[]` 放行，不拦截（兼容 MCP 客户端杂质字段）。
2. **fs_write 先读后写（仅约束覆盖）**：server 进程内维护已读路径集合（fs_read/cat/text_head/text_tail 成功读取即计入）；fs_write 目标已存在且不在集合 → EINVAL「先用 fs_read 读取再写入」。新建文件与 append:true 不受限。集合随进程重启清空为已知边界（保护降级不失效）。
3. **适用范围**：全部注册工具（含 run_command/shell_exec 等黑盒工具的参数层）；黑盒命令内容的语义检测不在本 ADR 范围（属危险目标守卫议题，见 memorial 004 D2/R4）。
4. **DSH 原生层联动**：write/edit 属 deepseek-harness 工具，同款治理以工单形式提交（memorial 004 sub-task/002）：schema strict 化或同款指纹纠错 + 覆盖前先读后写（harness 拥有会话历史，比 MCP server 更有条件判定「读过」）。
5. **时机**：0.x 发布前窗口实施（ADR-0007）。

## 后果

- 正向：混型误用在执行前被拦且报错自解释，一轮自纠；「没看就覆盖」的事故形态被堵死；单点实现全工具受益、维护成本低。
- 负向：多工具重名参数（如 path）存在指路多义的可能，依赖加权启发式；warnings 放行档对纯垃圾参数无防护（接受：其风险不可知也不可控）；先读后写给合法覆盖流程增加一次 read 往返的 token 开销；进程重启后集合清空。

## 替代方案

- **全 strict 一律拒**：所有未知参数直接 EINVAL。最简单，但报错无指路、对客户端杂质零容忍，误伤难排查。否决。
- **只警告不拦截**：零兼容风险，但对事故形态零防护——与立项动机矛盾。否决。
- **不做，依赖 AI 自愈**：事故已证明自愈依赖运气（恰好在会话内读过原文）。否决。
