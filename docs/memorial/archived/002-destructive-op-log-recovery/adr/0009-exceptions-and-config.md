# ADR-0009: 破坏操作保护的例外与配置——默认关闭、环境变量通道、低价值名单与大小阈值

状态：Accepted

日期：2026-08-20

来源：memorial 002-destructive-op-log-recovery（D2/D3/D6/D7/D9/D15）

## 上下文

ADR-0008 确立回收站型保护。但「所有破坏性操作都可恢复」若无条件执行，会带来三个现实问题：(a) 低价值路径（node_modules 等）进回收站纯属浪费；(b) 超大目标（rm -rf 10GB）全量备份成本不可接受；(c) 保护机制本身改变既有行为（兼容红线 ADR-0007：发布后只加不改，行为变更需借发布前窗口）。

候选配置通道：环境变量 / JSON 配置文件 / 每调用参数。

## 决策

**保护机制默认关闭，手动开启；全部配置走环境变量（进程级，启动时读取）；存在两类可恢复性例外：**

1. **低价值名单**：内置 `node_modules,.git,dist,build,.cache,__pycache__,target`（任意层级路径匹配），`WIN_SHELL_LOWVALUE_LIST` 逗号分隔**追加**；命中名单的目标直接真删/真覆盖，不备份。作用域覆盖所有破坏操作（含覆盖类）。
2. **大小阈值**：目标体积超 `WIN_SHELL_BACKUP_MAX_BYTES`（默认 1GB）跳过备份直接真删，仅记审计日志——独立于低价值名单（名单是「低价值」语义，阈值是「成本」语义）。

变量清单：`WIN_SHELL_PROTECT`（置 `1` 开启）、`WIN_SHELL_LOG_DIR`（默认 `D:\log`，下分 logs/ 与 backup/）、`WIN_SHELL_LOWVALUE_LIST`、`WIN_SHELL_BACKUP_MAX_BYTES`。

## 后果

- 正向：未开启时零行为变化（守住兼容红线与「无沙箱全权限」定位）；开启后 AI 高频场景（清 node_modules）无感知；错误与例外规则可预测、可文档化。
- 负向：默认关闭意味着多数用户首次使用时不享受保护（需读文档开启）；例外规则让「所有操作都可恢复」的承诺打了折，AI 需理解名单与阈值边界；环境变量通道牺牲了细粒度配置（无法按项目/按工具差异化）。

## 替代方案

- 配置文件（JSON）：可表达细粒度配置，但引入配置文件生命周期（路径解析、读写权限、热加载），与「零配置文件」的 stdio 部署形态不符。
- 每调用参数（permanent: true）：行为由 AI 每次显式声明，与「默认安全」目标冲突，且无法约束黑盒工具。
- 无例外全量备份：大目录/低价值路径成本不可接受，回收站机制将沦为负担。
