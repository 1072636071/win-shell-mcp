# Memorial 002 — 破坏性操作日志与恢复

**状态**：已完成（2026-08-20）

## 诉求

> 新需求：所有破坏性操作都要记录日志、日志默认放在 d盘/log，用户可以通过环境变量恢复。要保证破坏性所有操作都可以恢复。

即：win-shell-mcp 中所有破坏性操作（删除、覆盖、清空、移动等不可逆/可逆性弱的操作）都要记录操作日志；日志默认写入 D:\log；日志目录/行为可通过环境变量配置；目标是一切破坏性操作都可恢复（或至少可追溯）。

## 决策汇总

- **D1（2026-08-20）可恢复深度**：回收站型——破坏前将原数据移入备份区，提供还原工具；不做完整 undo 链。
- **D2（2026-08-20）低价值判定**：内置名单（`node_modules`、`.git`、`dist`、`build`、`.cache`、`__pycache__`、`target`，任意层级路径匹配）+ 环境变量追加；命中名单直接真删/真覆盖，不备份。
- **D3（2026-08-20）名单作用范围**：所有破坏操作（含覆盖类），不只 fs_rm。
- **D4（2026-08-20）回收站组织**：时间戳批目录——备份根 = 日志根/backup，每次破坏操作生成 `backup/<操作ID>/`（含 meta.json：原路径/操作/时间/工具参数/操作 ID）。
- **D5（2026-08-20）目录配置**：同根单变量——一个日志根环境变量，下分 logs/ 与 backup/。
- **D6（2026-08-20）功能开关**：默认不开启，手动开启（环境变量）；未开启时保持现有行为。
- **D7（2026-08-20）配置通道**：全部走环境变量（开关/目录/名单/阈值），启动时读取，进程级生效；不引入配置文件。
- **D8（2026-08-20）还原通道**：新增 `fs_restore`（按操作 ID 还原整批）+ `fs_trash_list`（列批次：操作 ID/原路径/时间/大小）。
- **D9（2026-08-20）还原冲突**：原位置已有新文件时冲突报错，由调用方决定；不静默覆盖。
- **D10（2026-08-20）日志形态**：审计流 `logs/operations.jsonl`（每破坏操作一行：时间/工具/参数/目标/操作 ID/备份路径/结果）+ 每批 meta.json 自包含。
- **D11（2026-08-20）记录粒度**：只记破坏性操作，非破坏操作不记录。
- **D12（2026-08-20）保护范围**：fs_rm、fs_write（覆盖）、fs_mv（覆盖）、fs_cp（覆盖 dest）、text_replace、archive_extract、net_download 全保护；git_* 不备份（自有 reflog/stash）；shell_exec/run_command 不备份但审计日志记录原始命令文本。
- **D13（2026-08-20）备份失败兜底**：失败即中止——备份失败则破坏操作不执行；错误返回优雅的 AI 可理解的语义化提示（原因 + 可行出路），由 AI 自行解决。
- **D14（2026-08-20）回收站生命周期**：不自动清理，由用户自己管理；不提供自动 TTL/容量淘汰。
- **D15（2026-08-20）环境变量清单**（agent 依授权裁定细节）：

  | 变量 | 默认 | 作用 |
  |---|---|---|
  | `WIN_SHELL_PROTECT` | 空（关闭） | 置 `1` 开启保护机制 |
  | `WIN_SHELL_LOG_DIR` | `D:\log` | 日志根：`logs/operations.jsonl` + `backup/<操作ID>/` |
  | `WIN_SHELL_LOWVALUE_LIST` | `node_modules,.git,dist,build,.cache,__pycache__,target` | 逗号分隔**追加**到内置名单 |
  | `WIN_SHELL_BACKUP_MAX_BYTES` | `1073741824`（1GB） | 目标体积超限 → 跳过备份直接真删，仅记审计日志 |

  前缀与项目名一致；名单为追加语义（内置不可移除）；大小阈值独立于低价值名单（成本维度 vs 低价值维度）。
