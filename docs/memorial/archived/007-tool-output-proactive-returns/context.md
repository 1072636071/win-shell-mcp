# Memorial 007 — 工具输出主动充分返回

状态：已完成

## 诉求

（用户原话）

> 因为LLM的输入token一般都很便宜，输出token一般都很贵，我们设计的这些工具，尽可能把信息返回处理，不要让LLM再走一轮。
> 可以多返回一些信息，信息保证极简。

追加诉求：

> 还有能不能支持批量调用，调用一串指令，可以提前写好断言。方便理想情况，一轮解决问题。

## 追问记录

- [2026-08-25] 方向定性：用户选「方向1：语义完整」——工具把 LLM 光靠参数无法确认的边界情况显式返回，改动集中在已有工具的字段补充。
- [2026-08-25] 新增诉求：支持**批量调用**——调用一串指令，可提前写好断言，理想情况一轮解决。倾向让确定性检查提前做掉，避免 LLM 为评估结果再走一轮。
- [2026-08-25] 批量形态：选方案1 `batch_run`（单 meta 工具）。
- [2026-08-25] 断言模型：方案1+4 —— 路径+操作符断言（eq/neq/gt/gte/lt/lte/in/re/truthy/falsy），省略 assert = 只要求该步成功。
- [2026-08-25] 步骤间引用：方案1 —— 模板串 `{{stepId.output.path}}` 插值；整个值恰好等于一个引用时保持原类型（bool/number），否则转字符串。
- [2026-08-25] 授权：其余实现细节由我自主裁决，只需 LLM 可用，不追求人类可读。

## 决策汇总

- 批量形态：选方案1 —— 新增单 meta 工具 `batch_run`，入参一串步骤，server 内顺序执行并按断言确定性校验。一次 MCP 调用解决一轮。
- 断言能力**纳入**：每步可附 `assert`。省略 = 只要求该步成功；写了则是 `[{ path, op, value? }]`，`op ∈ eq|neq|gt|gte|lt|lte|in|re|truthy|falsy`。无 eval，纯数据，可逐条失败归因。
- 步骤间依赖**纳入**：args 与 assert 值里写 `{{stepId.output.path}}` 模板串；整串=单引用时保持原类型，否则转字符串。
- 自主裁决细节（无 eval、确定性、极简）：
  - **执行顺序**：步骤按数组顺序串行执行；后续步骤可引用任意更早步骤的输出。
  - **短路**：任一步失败或其 assert 不满足时立即中止，不再执行后续步骤；返回里 `steps` 仅含已执行步骤的结果与判定。
  - **stepId**：每步可带可选 `id`（LLM 指定）；缺省时以 `step<N>`（1-indexed 序号）作为默认引用名。
  - **断言路径**：`path` 为点路径，访问该步 OK 结果展开后的顶层字段（如 `replaced`、`fs_rm.removed`）。
  - **batch 结果**：返回 `{ ok, steps: [{ id, tool, ok, data?, error?, assert? }], summary }`，其中 `ok` 仅当所有执行步骤均成功且断言通过；`summary` 极简文本。
  - **批内互斥**：步骤引用只允许指向已完成的步骤；不自引用、不前向引用。
