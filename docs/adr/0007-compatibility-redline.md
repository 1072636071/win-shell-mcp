# ADR-0007: 兼容性红线——发布前允许破坏，发布后只加不改

状态：Accepted

日期：2026-08-19

来源：memorial 001-command-coverage-extension（D5）

## 上下文

拓展现有命令（如 fs_read 加分页、text_grep 加递归）时，对下游 AI 客户端的兼容性要求需要红线。项目尚未发布（0.x），但定位是可发布开源产品，工具行为变更的影响面会随发布质变。

候选红线：

- **只加不改（additive-only）**：立即执行，只允许新增可选参数与输出字段。
- **SemVer 有限破坏**：major 版本允许破坏默认行为。
- **逐案评审**：不设红线，逐 PR 讨论。

## 决策

**分两阶段：**

1. **发布前（当前 0.x）**：允许破坏性修改，且应主动借此窗口修正不合理设计（如统一 fs_read/cat 区间语义、修复 text_replace 编码静默改写、text_diff 换真 diff 算法）。
2. **正式发布后**：只加不改（additive-only）——仅新增可选参数与输出字段；默认行为与既有字段永不变。历史设计瑕疵只能另开新命令修正。

## 后果

- 正向：发布前充分纠错，不把 0.x 的设计债带进 1.0；发布后下游零破坏风险，AI 调用习惯稳定，守住「确定性命令」定位。
- 负向：发布前窗口的破坏性修改要求批次内集中完成（ memorial 001 的 D8 清单即为此窗口的主要修正集）；发布后纠错成本变高（新命令替代旧参数）。
- 改默认行为的窗口随 1.0 发布永久关闭，属难逆转决策。

## 替代方案

- 立即只加不改：过早冻结，把已知正确性缺口（E-21/E-22）带进正式版。
- SemVer 有限破坏：MCP 客户端对版本感知弱，升级即踩坑，「确定性」承诺打折。
