# ADR-0016: 交互与输出设计总纲——四层优先级链

状态：Accepted

日期：2026-08-26

关联：ADR-0003（极简输出）、ADR-0015（batch_run）、memorial 007

## 背景

此前各优化目标零散地体现在不同 ADR 里，彼此没有明确的优先级排序：

- ADR-0003 追求**输出 token 最小化**（极简输出）。
- ADR-0015 提出「输入 token 便宜、输出 token 贵，理想情况一轮解决问题」。
- memorial 007 提出「工具输出倾向主动充分返回判别信息，避免为确认结果再走一轮」。

当这些目标冲突时（例如「输出精简」与「一轮解决」打架），缺少统一的裁决依据，只能凭直觉取舍。

## 决策

确立**四层优先级链**作为所有交互与输出设计的**总纲**，优先级从高到低：

1. **交互轮速最少** —— 用户输入轮次（对话往返次数）最少。
2. **LLM 请求次数最少** —— 对 LLM 发起的 API 调用次数最少。
3. **输出 token 最少** —— 工具返回 / 模型生成的 token 最少。
4. **输入 token 最少** —— 进入上下文窗口的 token 最少。

约束规则：**下游项永远是上游项的让步对象**。即——为少一轮可多请求；为少一次请求可多输出；为少输出可多输入。

关键认知：一次「用户输入」（一轮对话）内部可能包含 agent 的多次 LLM 请求（多步 tool call 循环）。因此前两项的关系是——**宁可在一轮对话内多请求几次 LLM，也要保证用户只输入一次就拿到最终结果**。

## 理由（权衡）

- **轮速 > 请求**：用户可见的往返成本最高（等待 + 每轮 LLM 重新理解上下文、重新起请求）；agent 内部多请求是隐藏成本，可接受。
- **请求 > 输出**：每次请求有固定开销（重读 context、重新推理），减少请求次数的收益高于压缩单次输出。
- **输出 > 输入**：本项目共识为「输入 token 便宜、输出 token 贵」（ADR-0015）——输出是逐 token 生成推理，输入可缓存；且输出会连锁变成下一轮的输入，省输出即间接省输入。

## 后果

- 收编 ADR-0003「极简输出」为本链第 3 项的具体化；memorial 007「避免再走一轮」为本链第 1 项的具体化。
- 后续所有工具的输出/交互设计、以及 PRD 审查，一律以本链为裁决依据。
- 目标冲突时按链裁决，不再凭直觉。

## 替代方案

- **只保留 ADR-0003「极简输出」单一原则**：无法处理「输出精简 vs 一轮解决」的冲突（曾出现为省输出反而多走一轮确认），被否决。
- **「输入 token 最少」优先于「输出 token 最少」**（常见直觉：context 更稀缺）：与项目共识「输入便宜、输出贵」相悖，且省输出能连锁省输入，被否决。
