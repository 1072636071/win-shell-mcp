# ADR-0003: 输出契约——极简输出 + verbose 开关 + 统一错误码

- 状态：已接受
- 日期：2026-08-18

## 背景

命令抽象层的输出直接决定 AI 客户端的 token 消耗与决策质量。需要决定：① 默认返回多少信息；② 需要完整数据时如何获取；③ 失败时如何表达错误。同时，多工具模块间出现了重复代码（`execFileAsync` 定义、`IS_WIN` 常量、错误→fail 转换），需要统一消除。

## 决策

1. **极简输出**：所有工具默认只返回 AI 决策所需的最小字段，长内容截断（默认 2000 字符）。
2. **verbose 开关**：需要完整数据时由调用方显式开启 `verbose`，经 `withVerbose(minimal, full, verbose)` 选择输出。
3. **统一错误码**：失败统一为 `{ ok: false, error: { code, message } }`，code 取自 `contract/errors.ts` 的标准码表（对齐 Node errno + 业务码）。
4. **共享模块消除重复**：
   - 命令执行机器集中在 `src/exec/run.ts`（深模块，接口只有 `runCommand`）；
   - 错误→fail 的唯一适配器是 `src/utils/errors.ts` 的 `toFail`（域逻辑用 `codedError` 抛携带业务码的错误）；
   - glob/正则转义集中在 `src/utils/glob.ts`；
   - 平台常量集中在 `src/utils/platform.ts`。

## 后果

**正面**
- token 高效：默认输出最小化。
- 错误码可被 AI 识别类别并决定重试策略。
- 重复逻辑（超时终止、编码解码、错误映射）有唯一归属，局部性强。

**负面 / 代价**
- 极简输出可能遗漏调用方需要的字段，需开 verbose 重试。
- 共享模块成为多域依赖，修改需全量回归。

## 备选方案（被否决）

- **默认完整输出**：token 消耗高，违背极简原则。
- **各工具自定义错误格式**：AI 无法统一识别错误类别。
