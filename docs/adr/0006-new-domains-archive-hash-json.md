# ADR-0006: 新命令域 archive / hash / json 的设立——语义独立即可成域

状态：Accepted

日期：2026-08-19

来源：memorial 001-command-coverage-extension（D6、D8）

## 上下文

命令覆盖审计（sub-task/001.md）发现三类高频缺口不属于现有八域：归档压缩/解压（P0）、文件哈希（P1）、JSON 路径取值（P1）。每类只有 1-2 个命令，是否值得独立成域存在分歧：

- **规模门槛派**：一域至少 3 个命令，不足就近并入现有域（压缩归 fs、哈希/JSON 归 text）。
- **语义独立派**：不设规模门槛，语义独立即可成域。
- **杂项域派**：设 util 域兜底收纳。

## 决策

**语义独立即可成域，不设最小规模门槛；拒绝 util 杂项域。**

- 新设三个域：`archive`（archive_create / archive_extract）、`hash`（hash_file）、`json`（json_get）。
- 论证：archive 是跨 tar/zip 的打包/解包独立场景，非纯文件读写；hash 基于 node:crypto 摘要计算，独立于文本行处理；json 是结构化数据路径取值，与 text 域「按行处理」范式不同。
- 每个新域回写 CONTEXT.md 决策清单。
- 未来新域沿用同一闸门：逐域论证（覆盖场景、不可替代性），但不设规模门槛。

## 后果

- 正向：域归属诚实，AI 导航语义清晰；微型域不硬塞进不相干的域。
- 负向：域数量从 8 增至 11（另有八域外补充组），微型域增多；需靠高质量工具描述维持可发现性。
- 可逆性：发布前（0.x）合并/拆分域的成本低；发布后域归属冻结（见 ADR-0007）。

## 替代方案

- ≥3 命令才成域：域数量可控，但导致「JSON 塞 text 域」式勉强归入，稀释域语义。
- util 杂项域：垃圾桶反模式，AI 无法预测域内容。
