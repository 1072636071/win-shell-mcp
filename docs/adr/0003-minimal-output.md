# ADR-0003: 输出精简原则——token 最小化

状态：Accepted

日期：2026-08-18

## 上下文

win-shell-mcp 覆盖八大命令域，AI 每次调用工具都会把返回内容读入上下文窗口，token 即成本。用户明确要求：**工具返回的结果集放弃多余的格式化，尽可能减少 token 消耗**。

## 决策

所有工具的输出遵循以下精简原则：

- 输出结构化 JSON，但只包含必要字段。
- 禁止装饰性格式化（表格边框、进度条、分隔线、艺术字、多余的空白/缩进）。
- 长输出默认截断，返回「摘要 + 明确的取更多方式」（如参数 `--limit` / 偏移量），不一次性倾倒全部内容。
- 不重复输出调用时已提供的上下文（如路径、参数、cwd）。
- 错误信息保持简短，附带可行动的下一步建议。
- 成功信息极简（如 `{"ok":true}`），不为凑结构输出冗余字段。

## 后果

- 正向：token 消耗显著下降，AI 上下文干净，减少噪音导致的误判。
- 负向：用户拿不到完整原始输出，需通过额外参数（如分页、`--full`）显式获取；每个工具都要精心设计精简 schema，增加实现成本。

## 替代方案

- 完整无截断输出：对用户友好，但消耗大量 token，被否决。
- 人类可读文本输出：适合人看，但不利于 AI 结构化解析，被否决。
