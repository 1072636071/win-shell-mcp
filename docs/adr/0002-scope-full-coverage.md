# ADR-0002: 范围策略——全命令域覆盖 + 可持续扩展

状态：Accepted

日期：2026-08-18

## 上下文

win-shell-mcp 的目标是「替换掉 AI 在 Windows 上反复出错的 cmd/PowerShell 命令」。

可行性分析识别出八大候选命令域：文件系统、文本处理、搜索、网络、进程、包管理、系统信息、Git。常见做法是先做 MVP（最小验证集），跑通后再扩展。

用户决策：**v1 即覆盖全部命令域，且后续持续补充更多**。

## 决策

- v1 覆盖全部八大命令域，不设 MVP 裁剪。
- 架构必须原生支持「持续扩展」：新命令以低成本注册接入，不得硬编码工具清单。
- 网络/包管理/Git 等已有成熟生态的域，也纳入本项目统一抽象层（而非依赖外部 MCP server），保证 AI 单入口调用。

## 后果

- 正向：AI 只需记住一个 MCP server，所有高频命令单入口覆盖，调用心智成本最低。
- 负向：v1 体量显著增大；对架构的可扩展性、工具描述质量、一致性要求更高。
- 需要引入**命令注册表（command registry）** 机制：每个命令域独立模块，声明式注册短名/别名/参数 schema/描述，server 启动时动态装载。

## 替代方案

- 核心四域 MVP：迭代快，但用户明确否决——痛点覆盖面不足。
- 最小验证集（文件+文本+逃生舱）：仅用于验证设计假设，不符合"替换全部易错命令"的目标。
