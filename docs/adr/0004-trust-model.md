# ADR-0004: 信任模型——默认全权访问（trust mode）

状态：Accepted

日期：2026-08-18

## 上下文

工具集含 `run_command` 逃生舱与进程域（`ps`/`kill`）。可行性分析建议"exec 命令做白名单/沙箱防注入"，但这是针对 shell 字符串执行的老思维——本项目已定 `run_command` 用 `spawn(executable, args)` 参数数组，**注入问题在架构上已消除**。剩余需要决策的是信任边界：AI 能碰哪些目录、哪些命令。

## 决策

- 采用**信任模式**：文件/进程/`run_command` 均全权访问，不做目录白名单、不做命令白名单。
- 依据：本项目定位是「替代 shell」，shell 本就全权；限制根目录会削弱逃生舱价值，且 `ps`/`kill` 等进程操作无法限定在目录内。
- 通过每个工具的 description 明确提示谨慎使用，把安全责任交给 AI 与宿主客户端。

## 后果

- 正向：与 shell 全权能力等价，逃生舱价值最大化，无需维护白名单配置。
- 负向：若宿主客户端不加以约束，工具集具备系统级破坏能力；依赖宿主侧的权限确认机制（如 TRAE/Claude 的工具调用确认）。

## 替代方案

- 文件限根目录 + 其余全权：安全裕度更高，但需配置、限制跨目录操作，被否决。
- 全限定（root + 命令白名单）：最安全但最不实用，逃生舱价值大打折扣，被否决。
