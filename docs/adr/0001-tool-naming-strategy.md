# ADR-0001: MCP 工具命名策略——短名主名 + 语义化别名

状态：Accepted

日期：2026-08-18

## 上下文

win-shell-mcp 的定位是「替换掉 AI 在 Windows 上反复出错的 cmd/PowerShell 命令」。

AI 训练语料以 Linux 环境为主，习惯 Unix 命令名（`ls`、`cat`、`grep`），到了 Windows 上命令名与参数语法全变，导致频繁报错。本项目把这些命令变成 MCP 暴露的结构化工具，内部用 Node 跨平台 API 实现。

这里有一个命名策略分叉：

- **语义化命名**（`read_file`、`list_directory`）：符合 MCP 生态惯例（官方 filesystem MCP 即如此），AI 靠工具描述理解用途。
- **Unix 短名直呼**（`ls`、`cat`）：AI 本能调用熟悉的命令名，替换感最强，但偏离惯例且可能引入 `rm -rf` 式语义混淆。

## 决策

**两者都要：Unix 短名作为主工具名，同时注册语义化别名。**

- 主名：Unix 短名，如 `ls`、`cat`、`grep`、`rm`。
- 别名：语义化名称，如 `list_directory`、`read_file`，指向同一实现。
- 每个工具的描述（description）中写明「≈ Unix 的 xxx」及 Windows 对应命令（如 `≈ dir`），帮助 AI 双向映射。

## 后果

- 正向：AI 用熟悉的命令名即可完成工作，调用成本最低；语义化别名兼顾 MCP 惯例与可读性。
- 负向：工具清单变长，实现需维护 主名→别名 的映射表；别名注册需额外处理避免与主名冲突。
- 改工具名会影响所有下游调用（客户端缓存、AI 习惯），逆转成本中等。

## 替代方案

- 仅语义化命名：干净但「替换易错命令」的意图传达弱。
- 仅 Unix 短名：调用直觉最强，但偏离 MCP 惯例，语义混淆风险高。
