# 装配原理与各模式装填后的形态

回答三个问题：系统提示是**怎么装填的**（流水线）、**为什么这样设计**（原理）、
8 个模式**装填完毕后长什么样**（形态）。事实核对基准：`deepseek-harness`
仓库 `packages/core/system-prompt/src/index.ts`（下称 *core*）。

提示词文本本身（各模式 persona 逐字）见 [提示词/README.md](提示词/README.md)；
本项目三模式的取舍见 [三模式提示词.md](三模式提示词.md)。

## 一、装填原理：注册表装配，不是常量

DSH 的系统提示**不存在一份完整文本**。`systemPrompt` 服务是一张注册表，
各插件在启动时往里塞片段（section），装配时按规则拼装。核心规则：

1. **片段带 `order`，按升序以空行拼接**。order 是稀疏整数（相邻至少差 10），
   便于机械检测意外碰撞；同名片段按名字确定性排序。整表见 *core:130*
   `FIRST_PARTY_SECTION_ORDER`（HARNESS_IDENTITY=-1000 … DELIVERABLE_FILE_REFERENCES=9000）。
2. **persona 只是 order 0 的普通片段**（名为 `deployment:persona`）。agent preset
   里的 `@deepseek-ai/dsh-persona` 行之所以能换掉部署默认 persona，是靠**同名
   影子替换**，不是特殊通道。
3. **`complete: true` 是权威裁剪开关**：装配收尾丢弃该片段以外**所有** section。
   多个 complete 片段并存直接抛错。
4. **`{{变量}}` 严格插值**：未知变量名抛错；插值只作用于 section 与运行时上下文，
   不作用于工具 schema。
5. **两条条件渲染**：`plan:policy`（order 500）只在 plan 模式激活期间非空
   （`plan-mode` 插件，退出即清空）；`ptc:only`（order 800）只在 PTC 模式下非空
   （`core/tools:861`，"run_code is the only tool you can call directly…"）。
6. **有些段落根本不是 system prompt**：`AGENTS.md`（agent-instructions）、
   运行时上下文快照都以 user 角色输入；工具 schema 走消息里的 tools 字段。
   它们在装配之外，`complete: true` 管不到它们（运行时上下文另由
   `includeRuntimeContext: false` 关闭）。

### 装填流水线（按时间顺序）

1. **宿主底座**：`systemPrompt` 服务启动即注册固定 opener
   `You are an AI agent powered by DeepSeek Harness.`（order -1000，
   `includeHarnessIdentity` 默认开）和空的部署 persona（order 0）。
2. **应用壳追加**：CLI/web 启动收尾若从源码 checkout 启动，`app-boot` 的
   `addHarnessSourceSection`（`packages/boot/app-boot/src/index.ts:820`）追加
   `harness:source`（order -900）——告诉模型 checkout 在哪、且 checkout ≠ 工作目录。
   生产安装无此段。
3. **web 宿主追加**：`dsh web` / web-app bundle 注入 `web:surface`（order -800，
   `packages/bundle/web-app/src/index.ts:248`）——GUI 地址、"this page" 指代、
   HMR 与重建规则。CLI 会话没有这段。
4. **preset 挂载（影子替换）**：选中某个 agent preset 后，其 `cordis.yml` 里的行
   逐条解析——`dsh-persona` 行影子替换 persona；`plan-mode` 行注入 `plan:policy`
   文本；各工具行注册工具与各自的 guidance section；`agent-instructions` 行只是
   开通 AGENTS.md 的读取（不进系统提示）。
5. **装配**：所有 section 按 order 升序拼接；条件段按当前状态决定非空或清空；
   `complete: true` 若在，收尾只留 persona；最后做 `{{插值}}`（model、cwd 等）。
6. **其余输入**：工具 schema 随消息下发；AGENTS.md 与运行时上下文按第 6 条规则
   走 user 角色。

## 二、各模式装填完毕后的形态

装载"底座三段"与否取决于启动环境，与选哪个模式无关：

| 段 | order | 出现条件 |
| --- | --- | --- |
| opener `You are an AI agent powered by DeepSeek Harness.` | -1000 | 默认恒在（`complete` 段之外会被裁掉） |
| `harness:source`（checkout 位置） | -900 | 仅从源码 checkout 启动 |
| `web:surface`（Web GUI 说明） | -800 | 仅 `dsh web` |

### DSH 官方 4 模式（均未开 `complete`，工具 guidance 全部在装）

- **standard（标准）**：底座三段 + persona（`You are a coding agent powered by
  the {{model}} model. Your working directory is {{cwd}}.`）+ 工具 guidance 带
  （order 900 `file-reference` 的 `@` 路径约定、1000–1500 的 bash/读写/检索
  工具用法、1600 jobs、2000/2100 web_search/web_fetch、2400 goal、2600 workflow、
  2700 ralph、2800 subagent）+ web 下再加 9000 的可点击文件引用收尾段。
  进 plan 模式后 500 位插入 `plan:policy`。**实测样本见下节**。
- **ptc（PTC）**：与 standard 同底座；工具坍缩为单一 `run_code`，加
  `ptc:only`（800）与 SDK 工具声明 guidance（5000 `tools:sdk`）。
- **minimal（极简）**：`complete: true` + `includeRuntimeContext: false`——
  **模型看到的系统提示只有一句** `You are a helpful software engineer assistant.`，
  没有 opener、没有任何 guidance。
- **cordis（创造）**：standard 全部内容 + 五段 persona（host/preset 两平面、
  preset 创作规则）+ `cordis` 工具自己的 guidance（2500）。

### 插件模式

- **liangshen（梁神，两阶段锚定）**：
  - 阶段 1（晋升前）：`tool-bootstrap` 把装配结果**过滤到只剩 persona 一段**
    （字节级复刻官方 Minimal 的 wire：持久 bash + str_replace_editor 双工具、
    无运行时上下文、只放行白名单消息）。
  - 晋升后：wire 切换为 PTC（`run_code` 单工具 + `ptc:only`/SDK guidance），
    persona 追加所选工作区路径；插件的 `LIANGSHEN_GUIDANCE` 公告段
    （order 150，中文，见 [提示词/dsh-liangshen.en.md](提示词/dsh-liangshen.en.md)）
    说明自身机制；workspace 指令与 skill 目录再延迟一步注入。

### 本项目 WShell 3 模式（全部 `complete: true` + `includeRuntimeContext: false`）

- **wshell-standard / wshell-batch**：模型看到的系统提示 = 一句话 persona
  （两者逐字相同，批量模式的差异只在工具目录放行 `batch_run`）。
  底座 opener 因 `complete` 被裁掉；`harness:source` / `web:surface` 同样被裁。
- **wshell-full**：同上，persona 为单段 852 字符，自持 plan 政策（plan 模式
  行为边界）与后台并行委派两条规则——因为 `complete` 把官方 `plan:policy`
  与 subagent guidance 一并丢弃了（取舍见 [三模式提示词.md](三模式提示词.md)）。
  注意：这三段在 wshell 里**不渲染**，所以上表底座三段对它们不成立。

## 三、实测样本：standard 模式在 Web GUI + 源码 checkout 下的装配结果

一次真实会话（工作区 `D:\work\space\dsh-web-ui-jx`，checkout
`D:\work\space\deepseek-harness`）系统提示逐段解剖：

| # | 段落内容（开头） | section | order |
| --- | --- | --- | --- |
| 1 | You are an AI agent powered by DeepSeek Harness. | `harness:identity` | -1000 |
| 2 | The DeepSeek Harness implementation checkout is at D:\work\space\deepseek-harness… | `harness:source` | -900 |
| 3 | You are interacting with the user through the DeepSeek Harness Web GUI at http://127.0.0.1:3080… | `web:surface` | -800 |
| 4 | You are a coding agent powered by the dots-studio/dots-3-note-preview:free model. Your working directory is D:\work\space\dsh-web-ui-jx. | persona（已插值） | 0 |
| 5 | Tokens prefixed with @ are workspace paths… | `file-reference` | 900 |
| 6 | Non-zero exits are reported as `[exit code: N]`… | bash guidance | 1000 |
| 7–11 | read / write / edit / glob / grep 工具用法各一段 | fs guidance | 1100–1500 |
| 12 | Track every background job id… | jobs guidance | 1600 |
| 13–14 | web_search / web_fetch 用法 | web guidance | 2000 / 2100 |
| 15 | goal 工具约束（resume 重挂、blocked 门槛） | goal guidance | 2400 |
| 16 | workflow 只在用户明确要求时用 | workflow guidance | 2600 |
| 17 | ralph 只在明确要求 Ralph loop 时用 | ralph guidance | 2700 |
| 18–19 | subagent / subagent_fork 默认后台并行 | subagent guidance | 2800 |
| 20 | When you successfully create or modify files, mention the primary outputs… | `ui:deliverable-file-references`（`packages/client/ui-deliverables/src/index.ts:24`） | 9000 |

同会话进 plan 模式时，500 位会插入 `plan:policy`；退出即清空。
对照本项目 wshell 三模式：这张表里**只有第 4 行**（换成 wshell 自己的 persona），
其余全部被 `complete: true` 裁剪——这就是两套形态的全部差别。
